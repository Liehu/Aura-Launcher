# P2.3-A：Contract & Architecture Closure

第一小批先做**架构冻结审计**。

不是重新设计，而是对目前已经完成的：

```text
launcher-domain
launcher-search
launcher-context
launcher-action
launcher-ipc
launcher-indexer
launcher-plugin-host
launcher-plugin-api
launcher-core
launcher-config
launcher-hotkey
launcher-providers
launcher-ui
launcher-workflow
launcher-mcp
launcher-ai
launcher-runtime
```

做最终边界审计。

## 核心检查项

### 1. Execution Lineage

冻结：

```text
Producer
   ↓
ActionResolver
   ↓
launcher-action
   ├─ validate()
   └─ execute()
   ↓
Effect Executor
   ├─ System
   ├─ PluginBroker
   └─ McpExecutor
```

必须确认不存在第二条 Effect Gateway。

尤其继续保持：

```text
launcher-action == ActionEngine
```

不要在 Core 再造一个 `ActionEngine`。

### 2. ExecutionId

最终规则：

```text
one logical execution attempt
        ↓
one ExecutionId
```

跨：

```text
Core
→ Plugin
→ PluginHost
```

保持同一个 ExecutionId。

MCP 同理。

Retry：

```text
Retry
→ new ExecutionId
```

Workflow step retry、Agent replan 都必须继续符合这一规则。

### 3. Runtime / Protocol / Execution 三种 ID

最终冻结：

```text
RuntimeId
ProtocolSessionId
ExecutionId
```

三者不能混用。

### 4. Generation Matrix

最终核对：

```text
FileGeneration
ApplicationCatalogGeneration
UserStateGeneration
ContextGeneration
RankingGeneration
Plugin/provider lifecycle generation
```

必须明确：

```text
谁递增
谁读取
谁进入 CacheKey
谁持久化
什么时候失效
```

这一部分应该成为 1.0 最重要的架构契约之一。

# P2.3-C：Reliability / Recovery Closure

重点测试真正的“坏情况”。

## 至少覆盖

```text
Plugin crash
MCP server crash
MCP protocol violation
MCP timeout
Indexer failure
DB corruption
Config corruption
Icon cache corruption
Process startup failure
Launcher crash
Repeated crash
Upgrade interrupted
Migration interrupted
```

最终每一种都必须有确定状态：

```text
Success
Retry
Stop
Quarantine
Recover
Degrade
```

不能出现：

```text
panic
silent success
silent data loss
infinite retry
```

同时重点检查：

```text
at-least-once
≠
exactly-once
```

不要为了测试方便产生错误的 exactly-once 假设。
