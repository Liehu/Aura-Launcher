# 2. P2.9 核心原则

P2.9 必须保持此前已经冻结的边界：

```text
System Capability
        ≠
Capability Grant

System Resolver
        ≠
Effect Authority

System Command
        ≠
Effect

Plugin Request
        ≠
Authorization

AI Proposal
        ≠
Execution

Workflow
        ≠
Effect Authority
```

最终 Effect 仍然只能：

```text
Validate
  ↓
Policy
  ↓
Approval
  ↓
launcher-action
  ↓
Effect
```

---

# 3. 为什么单独建立 System Integration Layer

此前各模块如果直接接 Windows API，最终会形成：

```text
AI ───────────────→ Win32
Workflow ─────────→ PowerShell
Plugin ───────────→ filesystem
Search ───────────→ ShellExecute
UI ───────────────→ clipboard
```

这会造成：

- 安全边界碎片化
- 权限模型不一致
- 审计无法统一
- 测试无法统一
- Mock 困难
- Windows API 与业务逻辑耦合
- Agent 很容易绕过安全层

P2.9 强制收敛为：

```text
               ┌─────────────┐
               │ Search      │
               ├─────────────┤
               │ Workflow    │
               ├─────────────┤
               │ AI          │
               ├─────────────┤
               │ Plugin      │
               └──────┬──────┘
                      ↓
            System Capability API
                      ↓
             Resolver / Policy
                      ↓
               launcher-action
                      ↓
                Windows Adapter
                      ↓
                 OS Effect
```

| Capability | 示例 |
|---|---|
| `system.app` | 启动/关闭应用 |
| `system.process` | 查询/终止进程 |
| `system.window` | 激活/移动/调整窗口 |
| `system.clipboard` | 读写剪贴板 |
| `system.file` | 复制/移动/删除文件 |
| `system.shell` | Shell 操作 |
| `system.uri` | 打开 URI |
| `system.notification` | 系统通知 |
| `system.power` | 锁屏/关机/重启 |
| `system.display` | 显示器信息 |
| `system.audio` | 音量/输出设备 |
| `system.network` | 网络状态 |

| `system.hotkey` | 全局快捷键 |
| `system.environment` | 环境信息 |
| `system.context` | 前台窗口/当前选区等上下文 |

# 5. Capability 分层

每个能力必须定义：

```text
Discovery
Read
Mutate
Privileged
Destructive
```

例如：

```text
system.process.read
system.process.terminate
```

而不是简单：

```text
system.process
```

---

# 6. 风险分类

继续采用 P2.7 的风险模型：

```text
L0 Informational
L1 Read-only
L2 Reversible
L3 Destructive
L4 Sensitive / Privileged
```

示例：

| 操作 | 风险 |
|---|---|
| 当前窗口标题 | L1 |
| 查询进程 | L1 |
| 复制文件 | L2 |
| 修改窗口位置 | L2 |
| 删除文件 | L3 |
| 终止进程 | L3 |
| 重启系统 | L3 |
| 修改敏感系统设置 | L4 |

# 7. SystemCommand

所有系统能力统一描述为：

```text
SystemCommand
```

核心结构：

```text
SystemCommand {
    command_id
    capability
    target
    input
    context
    risk_level
    confirmation_policy
}
```

注意：

```text
SystemCommand
```

不是：

```text
Effect
```

---

# 8. SystemTarget

目标必须结构化。

禁止让上层直接提供：

```text
"powershell.exe -Command ..."
```

作为通用执行入口。

例如进程：

```text
ProcessTarget {
    pid
}
```

窗口：

```text
WindowTarget {
    hwnd
}
```

文件：

```text
FileTarget {
    canonical_path
}
```

应用：

```text
AppTarget {
    identity
}
```

---

# 9. Target Identity

Target 必须尽量使用稳定身份。

例如：

```text
App:
    ApplicationIdentity

Process:
    PID + ProcessStartIdentity

Window:
    HWND + WindowGeneration

File:
    canonical path + file identity when available
```

禁止：

```text
display name
window title
filename
```

单独作为危险操作的唯一目标。

---

# 10. Process Identity

必须避免 PID reuse：

```text
PID = 1234
```

并不意味着：

```text
the same process
```

因此 ProcessIdentity 至少：

```text
pid
process_start_time / process_instance_id
```

终止进程之前必须重新确认身份。

---

# 11. Window Identity

窗口必须避免仅凭：

```text
title
```

定位。

推荐：

```text
HWND
ProcessIdentity
WindowGeneration
```

如果 HWND 已失效：

```text
WindowNotFound
```

不得自动猜测新窗口。

---

# 12. File Effect

文件系统操作必须分为：

```text
Read
Create
Write
Copy
Move
Rename
Delete
```

禁止：

```text
system.file = arbitrary filesystem access
```

---

# 13. File Safety

任何路径必须：

```text
Normalize
Canonicalize
Validate
Policy Check
```

禁止：

```text
..
absolute path escape
UNC escape
device path
junction escape
symlink escape
```

除非该能力显式定义允许。

---

# 14. Destructive File Operations

删除必须区分：

```text
Recycle
PermanentDelete
```

默认：

```text
delete = Recycle
```

永久删除属于更高风险操作。

---

# 15. File Transaction

对于可逆操作：

```text
Prepare
→ Execute
→ Verify
```

如果可恢复：

```text
Rollback
```

例如：

```text
Move
Copy
Rename
```

需要记录：

```text
source
destination
previous_state
result
```



# 28. Adapter Architecture

```text
launcher-system
    │
    ├── process
    ├── window
    ├── clipboard
    ├── filesystem
    ├── shell
    ├── notification
    ├── power
    └── settings
             │
             ▼
      Windows Adapter
             │
      ┌──────┼──────┐
      ▼      ▼      ▼
    Win32   COM    Shell
```

业务代码不得散落 Win32 调用。

# 35. Confirmation

所有 L3/L4 默认：

```text
RequireConfirmation
```

批准数据必须：

```text
one-time
scope-bound
target-bound
run-bound
expiry-bound
```

不能保存：

```text
confirmed=true
```

作为永久授权。

---

# 36. Re-validation

执行前再次：

```text
Resolve
→ Validate
→ Policy
→ Confirm
→ Execute
```

尤其：

```text
Process
Window
File
```

等动态资源必须重新检查。

---

# 37. Stale Target

以下情况视为：

```text
StaleTarget
```

例如：

```text
window closed
process restarted
file moved
file identity changed
clipboard changed
```

系统不得静默选择新目标。

---

# 38. Retry

System Effect：

```text
at-least-once
```

因此：

```text
timeout
```

不表示：

```text
not executed
```

Retry 必须：

```text
new ExecutionId
```

对于非幂等 Effect：

```text
require explicit retry policy
```

---

# 39. Idempotency

标记：

```text
Idempotent
ConditionallyIdempotent
NonIdempotent
Unknown
```

例如：

```text
SetVolume(50)
    Idempotent

CloseWindow
    ConditionallyIdempotent

RestartComputer
    NonIdempotent
```

Unknown：

```text
默认禁止自动 retry
```
