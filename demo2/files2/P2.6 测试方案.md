# Aura Launcher P2.6 测试方案

## Workflow 2.0

---

# 1. 测试模型

P2.6 测试必须围绕：

```text
Graph Correctness
State Machine Correctness
Persistence Correctness
Recovery Correctness
Concurrency Correctness
Approval Security
UI Correctness
Performance
```

---

# 2. Graph Tests

## Valid

```text
A → B
A → B
A → C
B → D
C → D
```

## Invalid

```text
A → B → A
```

```text
A → MissingNode
```

```text
duplicate NodeId
```

```text
missing Entry
```

必须全部被 Validator 拒绝。

---

# 3. Condition Tests

测试：

```text
true
false
numeric compare
string compare
boolean
missing variable
invalid expression
```

要求：

```text
condition evaluation deterministic
```

---

# 4. Variable Tests

测试：

```text
input → variable
step output → variable
branch scoped value
join
missing variable
invalid path
```

重点验证：

> 并发 branch 不得产生未定义的 implicit last-writer-wins。

---

# 5. State Machine Tests

Run：

```text
Created
Queued
Running
Paused
Recovering
Succeeded
Failed
Cancelled
```

Step：

```text
Pending
Ready
Resolving
Resolved
WaitingApproval
Executing
Completed
Skipped
Failed
```

测试：

```text
合法 transition
非法 transition
重复 transition
restart transition
```

---

# 6. DAG Scheduler Tests

测试：

### Sequential

```text
A → B → C
```

### Branch

```text
A
├─ B
└─ C
```

### Join

```text
B ─┐
   ├→ D
C ─┘
```

### Parallel

B/C/D 同时 ready。

验证：

```text
max_parallel_nodes
```

不得超限。

---

# 7. Determinism

同一：

```text
Definition
Input
Context
Provider state
```

执行：

```text
>=1000
```

最终：

```text
node states
variables
transitions
failure classification
```

必须一致。

---

# 8. Durable Persistence Tests

测试：

- create run
- queue
- start
- node completion
- checkpoint
- variables
- approval
- failure
- completion

每个 committed state 都必须可 reload。

---

# 9. Crash Recovery

故障点至少：

```text
before resolve
after resolve
before validate
after validate
before execute
during execute
after execute
before checkpoint
after checkpoint
```

Recovery 不得盲目假设：

```text
Effect 未发生
```

---

# 10. Retry

验证：

```text
attempt = 1
execution_id = X
↓
retry
↓
attempt = 2
execution_id = Y
```

必须：

```text
X != Y
```

同时：

```text
attempt <= max_attempts
```

---

# 11. Human Approval Tests

测试：

- request approval
- approve
- reject
- cancel
- expire
- duplicate approve
- wrong run
- wrong node
- stale approval
- replay

必须保证：

```text
Approval cannot cross Run boundary
```

---

# 12. Trigger Tests

测试：

```text
Manual
Hotkey
Plugin
Schedule
AI/MCP
```

所有 Trigger 最终只能产生：

```text
WorkflowRunRequest
```

不得绕过 Queue / Scheduler / ActionResolver。

---

# 13. Queue Tests

验证：

- persistence
- ordering
- dedup
- restart
- queue full
- cancellation
- recovery

必须：

```text
queue depth <= configured limit
```

---

# 14. Editor Tests

验证：

- create node
- delete node
- connect
- disconnect
- condition
- input
- retry
- approval
- save
- load
- import
- export
- undo
- redo
- invalid graph

UI 操作不得产生 Effect。

---

# 15. Version Tests

创建：

```text
Definition v1
Run v1
```

然后：

```text
Definition v2
```

必须保证：

```text
Run v1 → v1
```

不能自动切换。

---

# 16. Security Tests

至少：

```text
approval replay
wrong run approval
wrong node approval
forged workflow state
forged capability
persisted confirmed flag
persisted ResolvedAction
trigger bypass
editor bypass
```

必须：

```text
S0 = 0
S1 = 0
S2 = 0
```

---

# 17. Stress

建议 baseline：

```text
100 active workflow runs
```

每 Run：

```text
20 nodes
```

包含：

```text
2–4 parallel branches
```

验证：

- scheduling
- checkpoint frequency
- RSS
- queue
- task count
- recovery

---

# 18. Performance

建议目标：

| Metric | Budget |
|---|---:|
| Graph validation P95 | ≤5ms |
| Schedule decision P95 | ≤2ms |
| Checkpoint P95 | ≤10ms |
| Recovery decision P95 | ≤20ms |
| Approval event P95 | ≤5ms |
| Queue enqueue P95 | ≤2ms |

Workflow runtime 不得明显侵占 Launcher idle resource budget。

---

# 19. Soak

至少：

```text
30 min runtime soak
1000 workflow runs
10000 node transitions
```

必须观察：

- memory
- task
- checkpoint
- queue
- state corruption
- stale approval
