# Aura Launcher P2.5 开发设计规范

**阶段名称：Search Intelligence 1.0**

**状态：DRAFT v0.1**

**基线：Launcher 1.0 / P2.4 COMPLETE**

**工作目录：** `demo2/native-launcher/`

---

# 1. 阶段目标

P2.5 的目标不是简单增加更多 Provider，而是把 Launcher 现有的：

```text
Query
  ↓
Normalize
  ↓
Provider Fan-out
  ↓
Candidate Merge
  ↓
Ranking
  ↓
UI
```

升级为：

```text
User Input
    ↓
Query Normalizer
    ↓
Query Understanding
    ↓
Intent / Filter Detection
    ↓
Search Strategy
    ↓
Bounded Concurrent Fan-out
    ↓
Partial / Complete Aggregation
    ↓
Identity Merge
    ↓
Deterministic Ranking v2
    ↓
Explainability
    ↓
UI
```

最终目标：

> 在 Provider 数量增加、索引规模增加、查询复杂度提高以后，搜索仍然保持低延迟、确定性、可取消、可降级、可解释。

---

# 2. P2.5 基线

P2.4 已经将：

- Application Catalog 2.0
- File Index Maintenance 2.0
- Plugin Control Plane
- Plugin SDK / CLI / Diagnostics
- Recovery / Reliability

作为基础设施收口。

1.0 搜索已经具备：

- deterministic ranking
- Identity dedup / merge
- history / recency / context boost
- SearchSession stale-query guard
- Application Catalog authoritative read path
- File Index + generation
- Search Cache

因此 P2.5 不允许重新定义这些基础语义。

# 5. 架构

```text
┌──────────────────────┐
│ UI / Hotkey          │
└──────────┬───────────┘
           │
           ▼
┌──────────────────────┐
│ Core::search()       │
└──────────┬───────────┘
           │
           ▼
┌────────────────────────────┐
│ SearchCoordinator          │
│                            │
│ QueryNormalizer            │
│ QueryUnderstanding        │
│ StrategyPlanner            │
│ ProviderScheduler          │
│ ResultAggregator           │
│ IdentityMerge              │
│ Ranker                     │
│ ExplanationBuilder        │
└──────┬───────┬─────────────┘
       │       │
       ▼       ▼
     App     File / Plugin / Workflow
```

必须保持：

```text
Search != Action Authority
```

Action 仍然只能经过：

```text
ActionProposal
    ↓
ActionResolver
    ↓
launcher-action::validate()
    ↓
launcher-action::execute()
    ↓
Effect
```

P2 Cross-Cutting Contracts 已明确规定：Action 唯一执行权在 `launcher-action`，Search/Cache/Favorites/Context/Icon 只能提供信号，Plugin/MCP/AI metadata 也不能转化为 capability。

# 7. Intent

定义：

```rust
pub enum SearchIntent {
    Application,
    File,
    Folder,
    Command,
    Plugin,
    Workflow,
    Mixed,
    Unknown,
}
```

Intent 只是：

```text
routing signal

retrieval hint
```

绝对不是：

```text
authorization
capability
execution authority
```

# 8. Query Understanding

第一版必须完全 deterministic。

输入：

```text
chrome
*.pdf
D:\Projects
cmd:ipconfig
记事本
jsb
```

输出：

```text
normalized_query
tokens
intent
filters
language_hint
pinyin_variants
```

不得依赖：

- LLM
- network
- filesystem
- current time

---

# 9. Explicit Filter Syntax

建议支持：

```text
app:chrome
file:pdf
folder:project
cmd:ipconfig
wf:backup
plugin:calculator
```

规则：

1. 显式 filter 优先于推断。
2. 未知 filter 安全降级。
3. Parser 不产生 Action。
4. Parser 不访问外部资源。
5. Filter 不得通过 ranking hack 实现。

---

# 10. Search Strategy

定义：

```rust
pub struct SearchStrategy {
    pub providers: Vec<ProviderPlan>,
    pub max_parallelism: usize,
    pub soft_timeout_ms: u64,
    pub hard_timeout_ms: u64,
    pub allow_partial: bool,
    pub cancel_on_superseded: bool,
}
```

约束：

- max_parallelism 必须有上限。
- provider timeout 必须 bounded。
- global hard deadline 必须 bounded。
- provider timeout 不影响其他 provider。
- supersede 时旧 query 必须尽快取消。

# 11. Provider Contract v2

Provider 可以声明：

```rust
pub struct ProviderCapabilities {
    pub intents: Vec<SearchIntent>,
    pub supports_empty_query: bool,
    pub max_results: usize,
    pub expected_latency_ms: u64,
}
```

这些字段只能用于：

```text
routing
scheduling
ranking hint
```

不得用于：

```text
capability grant
trust grant
authorization
confirmation
```

# 12. Bounded Concurrent Fan-out

P2.4 的顺序 Provider 执行：

```text
App → File → Workflow → Plugin
```

P2.5 改为：

```text
             ┌─ App
             ├─ File
Query Plan ──┼─ Workflow
             └─ Plugin
```

但是：

> 并发不是 `spawn everything`。

必须使用：

```text
Semaphore
bounded queue
fixed worker pool
```

禁止：

```rust
for provider in providers {
    tokio::spawn(...)
}
```

这类无界模型。

---

# 13. Timeout Model

定义三级 timeout：

```text
Provider Timeout
Global Soft Deadline
Global Hard Deadline
```

状态：

| 状态 | 意义 |
|---|---|
| Complete | 完整结束 |
| Partial | 已得到可展示结果，仍有任务运行 |
| TimedOut | Global hard deadline 到达 |
| Cancelled | 被 supersede/cancel |
| Failed | 整体不可用 |

其中：

```text
Partial != NoResult
```

# 14. Deterministic Result Merge

绝对禁止：

```text
provider completion order
→ final UI order
```

正确流程：

```text
Provider Results
    ↓
Canonical Identity
    ↓
Candidate Merge
    ↓
Score
    ↓
Stable Sort
```

稳定 tie-break：

```text
identity_key
provider_id
command_id
```

# 15. FTS5

## 15.1 定位

FTS5 只负责：

```text
retrieval
```

不能直接决定：

```text
final ranking
```

正确架构：

```text
FTS5
 ↓
Candidate[]
 ↓
Identity Merge
 ↓
Ranking v2
```

## 15.2 默认索引字段

P2.5 默认覆盖：

- application name
- file name
- folder name
- keyword
- alias
- pinyin

不默认索引文件正文。

---

# 16. LIKE Fallback

必须保留：

```text
FTS5
  ↓ failure
bounded LIKE
```

要求：

- FTS migration failure 不损坏数据库。
- FTS rebuild failure 不导致 Search unavailable。
- FTS5 初始化失败可以降级到 LIKE。

因此 P2.5 不允许删除原有 bounded LIKE 路径。

---

# 17. Pinyin

至少支持：

```text
记事本
jishiben
jsb
```

支持：

- full pinyin
- initials
- mixed query
- Chinese + English
- Unicode

Pinyin 不得作为：

```text
IdentityKey
CommandId
PluginId
Capability
```

只是 retrieval / ranking signal。

---

# 18. Ranking v2

现有 invariant 必须保持：

```text
exact > prefix > contains > fuzzy
```

在其上加入：

```text
intent
pinyin
history
recency
context
provider_hint
```

核心 invariant：

> Boost 只能改变已有候选的排序，不得创造新候选。

# 19. Explainability

建议：

```rust
pub struct ScoreExplanation {
    pub lexical: f32,
    pub intent: f32,
    pub type_prior: f32,
    pub history: f32,
    pub recency: f32,
    pub context: f32,
    pub provider_hint: f32,
    pub pinyin: f32,
    pub total: f32,
    pub matched_fields: Vec<MatchField>,
}
```

必须：

```text
actual ranking calculation
        =
explanation calculation
```

不得维护两套算法。

---

# 20. Identity Merge

继续遵守 1.0：

```text
Application/File/Folder
→ normalized target path
```

```text
Command/Plugin/MCP
→ provider_id + id
```

Merge 后必须保留：

- subtitle
- alternative actions
- source metadata
- explanation evidence

---

# 21. Cache / Generation

如果新增：

```text
QueryUnderstandingGeneration
SearchStrategyGeneration
```

必须先登记到：

`P2-CROSS-CUTTING-CONTRACTS.md`

Generation 规则：

```text
committed state change
        ↓
generation++
```

禁止：

```text
event count == generation
timestamp == generation
request count == generation
```

已有横向契约明确要求 Generation 表示“已提交的数据版本”，失败不递增。
