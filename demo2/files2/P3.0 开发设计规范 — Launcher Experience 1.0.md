**状态：FROZEN DESIGN DRAFT（P0–P2 三批，B3+ 后置项见 §9）**

---

# 1. 阶段定位

P3.0 不是新平台能力阶段。P3.0 是：

> **把 P2.4–P2.10 已建成的引擎能力，翻译成用户可感知的体验。**

对标：Raycast / uTools / Wox 的"手感基线"。P2.10 评审已确认架构无待修项，
本阶段**不新增运行时权威路径**，全部改动位于呈现层与搜索评分层。

# 2. 非目标

```text
不改六份 FROZEN 契约语义（UI/COMMAND/ACTION/PLUGIN/WORKFLOW/VISUAL）
不新增运行时权威路径（一切执行仍经 Resolver → Engine）
不做云端同步 / 账号 / 跨设备
不做 Marketplace 服务端（P3.x Distribution 独立阶段）
```

# 3. 红线（继承 + 新增）

继承：UI 纯投影（INV-035~037）、stable id、UI-CONTRACT 三 Mode、
Motion ≤200ms、VR 基线确定性。

新增：

```text
UX-R1  模糊匹配是纯函数：同 (candidate, query) 恒同分，无 IO/时钟/随机
UX-R2  即时答案只读——求值过程不得产生 Effect/IO/网络；Enter 的动作
       是"复制"，经既有 ActionKind::Copy 路径
UX-R3  动画在 LAUNCHER_SNAPSHOT_DIR 模式下必须禁用（VR 基线确定性）
UX-R4  设置写入只允许白名单字段（§F04），写入前原子替换，失败保留原文件
```

# 4. Batch B0 — P0 搜索手感与即时反馈

## F01 模糊子序列匹配（launcher-search）

- 新模块 `crates/launcher-search/src/fuzzy.rs`：

```text
pub fn fuzzy_score(candidate: &str, query: &str) -> Option<FuzzyScore>
pub struct FuzzyScore { pub score: f32 }   // None = 不是子序列
```

- 匹配规则（确定性，全小写折叠后比较）：
  ```text
  子序列不成立            → None
  完整前缀命中            → 基础分 100
  词边界（空格/分隔符）命中 → 每边界 +12
  连续段                  → 每连续字符 +6（段越长额外 +段长）
  gap 惩罚                → 每跳过字符 -1.5（上限 -30）
  query 空或 candidate 空 → None（空查询走现有 recent 视图）
  ```
- 应用面：`Command.title` + `keywords` + 拼音串（initials 与 full）。
- 集成：`score_with_parts` 增加模糊分量（贡献上限 40 分），**不改既有
  分量权重**；FTS/前缀命中与模糊命中在去重后合并排序。
- 范围：catalog 常驻命令（apps/插件命令/工作流/设置/上下文）全量参与；
  文件索引仍走 FTS/LIKE（B0 不做全库模糊）。

## F02 搜索防抖 + 内存热路径

- 宿主（launcher-app）对 `query-changed` 增加 **70ms debounce**；
  取消语义沿用现有 SearchSession（query supersession，ADR-0004）。
- 热路径：debounce 到期后先做**目录内存匹配**（F01，纯内存，目标
  P95 < 5ms@10k 候选）立即出结果；文件索引（FTS）结果随后合并。
- 空 query 行为不变（recent/上下文视图，不经过 debounce）。

## F03 即时答案（launcher-core 新 provider `answers`）

- 触发：query 去空格后以 `=` 开头，或整体匹配"纯算式"文法
  （数字/运算符/括号/百分号，无字母）。
- 求值：**复用 `launcher_domain::expr` 的 `parse_expr + evaluate`**，
  RefResolver 为空（纯常量表达式）——安全边界天然成立（无变量、无
  函数、无 IO；UX-R2）。
- 呈现：Main 模式顶部固定一张"Answer"结果行（表达式 = 结果），
  Enter = 复制结果（`ActionKind::Copy`，既有路径）。
- 解析失败/除零/溢出 → 不显示 Answer 行，降级为普通搜索。
- 优先级：Answer 行永远第一，普通结果照常列于其后。

## F04 原生设置面（launcher-app 新 provider `settings-ui`）

- 查询 `settings` / 空查询固定入口行 "Open Settings"（复用现有 id）。
- 设置项以**命令 + ActionPanel 动作**呈现（不新增 UI Mode）：
  ```text
  settings:theme      → 循环 dark/light/system（写 config.theme）
  settings:hotkey     → 引导编辑 config（打开文件定位行）
  settings:index      → 列出/增删索引目录（写 config.index_dirs）
  settings:autostart  → 开关（写 config.autostart + autostart::set_autostart）
  settings:reindex    → 触发全量重建（确认门，沿用 requires_confirmation）
  ```
- 写入：launcher-config 既有 `save()` + **原子替换**（临时文件 + rename，
  UX-R4）；热重载链路已存在（MUST-2），无需新机制。
- 本批不做：热键捕获 UI（引导到配置文件）、每设置项独立面板。

# 5. Batch B1 — P1 视觉与信息密度

## F05 主题：dark / light / system

- `theme.slint` tokens 参数化：暗色系（现值）与亮色系两套调色板，
  accent 色继续来自 config。
- config 新增 `theme_mode = "dark" | "light" | "system"`（默认 dark，
  保持现状兼容）。
- `system`：弹窗打开时读 Win32 `AppsUseLightTheme` 注册表（读操作，
  非 Effect）。
- 所有组件必须经 Theme tokens 取色（已是红线），无硬编码色残留。

## F06 微动效

- 弹窗出现：120ms 透明度淡入（0→1）；
- 选中切换：≤80ms 背景色过渡；
- 结果列表出现：≤120ms 透明度 + 4px 位移；
- 全部 ≤200ms（VISUAL-DESIGN-SPEC Motion 红线）；
- **UX-R3**：`LAUNCHER_SNAPSHOT_DIR` 模式禁用动画（VR 基线确定性）；
- 实现载体：Slint `animate` 声明式属性动画，不用定时器线程。

## F07 结果元数据 + 详情面板

- 文件类结果行副标题区增加元数据段：`大小 · 修改时间 · 父目录尾段`。
- `Tab` 键切换右侧详情面板（现窗口宽 640 → 面板模式下 960，规格
  上限内）：完整路径、类型、修改/创建时间、（文件）图标大图。
- 面板是纯投影（只读呈现选中结果的既有数据），不新增解析。

## F08 自绘基础控件

- SearchBox 的 LineEdit 替换为自绘（保留 key-pressed 拦截协议不变）；
- Button → 主题化按钮组件（hover/press/focus 态）；
- 契约不变：SearchBox 仍不解释查询（UI-CONTRACT §9.1）。

# 7. 架构结果

```text
query → [debounce 70ms] → 内存模糊匹配（apps/插件/工作流/答案）
                        ↘ FTS/LIKE（文件全库）
                合并去重 → rank_with_boost（含模糊分量）
                       ↓
        Main 模式结果列表（Answer 行固定首位）
                       ↓
   Enter / ActionPanel —— 权威链不变（Resolver → Engine）
```
