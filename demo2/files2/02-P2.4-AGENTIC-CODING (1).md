# Aura-Launcher P2.4 — Agentic Coding Specification v0.2

> Baseline: Launcher 1.0 RC1
> Purpose: turn P2.4 into executable Agent Tasks
> Scope: P24-000, P24-A01..A06, P24-B01..B06, P24-C01..C06
> This document is normative for Agent execution.

## 1. Agent lifecycle

Every task MUST follow:

```text
Inspect -> Plan -> Implement -> Test -> Review -> Report
```

Before editing:

1. Read `AGENTS.md`.
2. Read the task's Inputs.
3. Inspect the current implementation and tests.
4. Check frozen contracts and ADRs.
5. State the files that will be touched.

After editing:

```bash
cargo fmt --check
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
```

Run the narrower task tests first; run the full workspace gate before task closure.

## 2. Universal forbidden behavior

An Agent MUST NOT:

- bypass `ActionResolver` / `launcher-action`
- change frozen public contracts without ADR
- put blocking IO/CPU on the UI thread
- introduce unbounded queues, maps or caches
- duplicate runtime dispatch logic
- rewrite a stable subsystem merely to satisfy a task
- update a benchmark baseline only to make a regression disappear
- silently delete user/security state during recovery
- treat external plugin/AI/MCP metadata as authority

Every task report MUST use:

# 8. Cross-cutting hard-stop rules

Agent MUST report `BLOCKED` rather than improvise when:

- a frozen contract would need breaking changes
- the proposed change crosses a process/authority boundary not covered by the task
- a migration would silently lose user/security data
- the only apparent recovery is unbounded retry/full-system rebuild
- an external metadata field would need to become trusted
- an unrelated existing test failure prevents validation
- the task's allowed files are insufficient

Do not create “temporary” bypasses that violate these rules.
