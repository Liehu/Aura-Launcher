# Aura-Launcher P2.4 — Agentic Coding Specification v0.1

## 1. Agent operating contract

Every task follows:

```text
Inspect
→ Plan
→ Implement
→ Test
→ Review
→ Report
```

Never skip Inspect or Test.

An agent may modify only files within the task's allowed scope. Unrelated findings must be reported separately.

## 2. Universal rules

### Must

- Read root `AGENTS.md`.
- Read relevant contracts and ADRs.
- Search existing abstractions before creating new ones.
- Add tests for every new public API.
- Add benchmark/rationale for performance-sensitive changes.
- Add concurrency tests or explicit reasoning for concurrency changes.
- Preserve frozen identifiers and generations.
- Run formatting, build, clippy and relevant tests.

### Must not

- bypass `ActionResolver` / `launcher-action`
- change public contracts without ADR
- introduce UI-thread blocking
- add unbounded collections/caches
- duplicate runtime dispatch logic
- introduce a parallel implementation of an existing provider without explicit task scope
- update a baseline merely to make a test pass

## 3. Task execution record

Every task starts with:


# 9. Universal completion gate

An agent may mark a task complete only if:

1. Allowed scope respected.
2. No frozen contract broken.
3. Relevant tests pass.
4. Workspace build/clippy/format pass where required.
5. Performance impact measured or explicitly proven irrelevant.
6. Completion report is filled in.
7. Gate ID is PASS.
