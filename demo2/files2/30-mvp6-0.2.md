# R1 是这次最值得保留的修复

`is_primary` 不应该由 UI 根据数组位置推断。

现在应该明确：

```text
Command::primary_action()
        ↓
first Ready
        ↓
is_primary = true
```

然后：

```text
ActionPresentation
{
    id,
    title,
    enabled,
    reason,
    shortcut,
    is_primary
}
```

UI 只消费：

```text
is_primary
```

这非常重要，因为现在：

```text
actions[0] = Disabled
actions[1] = Ready
```

UI 仍然必须显示：

```text
actions[1]  → Enter
```

而不是：

```text
actions[0]  → Enter
```

因此这一修改应该直接进入 UI Contract，而不仅仅作为实现细节。

# R2 也应该冻结成非常明确的行为

你现在把：

> 自动刷新

和：

> 下一次 invocation 时重新解析

分开，是正确的。

当前 v0.x：

```text
Context changes
      ↓
existing Action becomes stale
      ↓
user invokes
      ↓
reject + non-blocking feedback
```

而不是：

```text
Context changes
      ↓
ActionPanel automatically mutates
```

所以 UI Contract 可以直接写：

> **Context changes do not autonomously mutate the current Action selection in v0.1. Re-resolution occurs as part of a subsequent invocation lifecycle.**

这会避免以后 UI 团队为了“看起来更智能”偷偷加入实时刷新。

# R5：Accessibility 这次也应该直接进入 Contract

最低要求：

```text
Every meaningful state MUST have
at least one non-color representation.
```

因此：

```text
Disabled
```

不能只：

```text
opacity 50%
```

还必须有：

```text
reason text
```

例如：

```text
⚠ Requires clipboard.write
```

Workflow：

```text
Paused
```

不能只：

```text
yellow indicator
```

还必须有：

```text
⏸ Waiting for confirmation
```

Confirmation：

```text
Confirm
```

不能只：

```text
border / color
```

还必须有：

```text
Enter Confirm
Esc Cancel
```

这会让键盘 UX、视觉 UX、辅助技术形成一致语义。

# 一个重要的设计边界

UI-CONTRACT 不应该定义：

```text
“什么情况下是 ConfirmationRequired”
“什么情况下是 StaleContext”
“什么 Action 需要 shell.execute”
“什么时候 Retry”
```

这些已经属于：

```text
ActionResolver
FailureClassifier
Workflow
```

UI Contract 只定义：

```text
给 UI 一个什么状态
→ UI 怎么显示
→ 用户能做什么
→ 事件传回哪个 stable ID
```

也就是：

```text
Core semantics
      ↓
Presentation Model
      ↓
UI Contract
      ↓
Slint
```

而不是：

```text
Slint
 ↓
自己推导 Core semantics
```
