# Aura-Launcher P2.4 — Acceptance Specification v0.1

## 1. Definition of done

P2.4 is **Closed** only when every mandatory acceptance criterion is PASS.

A task with passing code but missing test, Gate, contract review or completion report is not Closed.

## 2. Acceptance states

| State | Meaning |
|---|---|
| Closed | implementation + tests + Gate + docs complete |
| Core Slice | usable core exists but a defined lifecycle/product gap remains |
| Experimental | technical validation only |
| Planned | approved but not implemented |
| Deferred | intentionally postponed |
| Rejected | explicitly not pursued |

---

# 3. P2.4-0 Acceptance

## AC-000

Must have:

- one authoritative Launcher 1.0 baseline
- no stale test counts in normative docs
- release gate points to the same baseline
- all deferred 1.0 items explicitly categorized

Gate:

```text
G-BASE = PASS
```

---

# 4. P2.4-A Acceptance

## AC-A01 — Identity

PASS when:

```text
same semantic executable/package → same identity
different targets → different identities
normalization is deterministic
identity resolution has no IO
```

## AC-A02 — Schema

PASS when:

```text
fresh install works
migration works
backup/recovery behavior documented
generation is persisted
schema version is explicit
```

## AC-A03 — Reconciliation

PASS when:

```text
add
update
remove
duplicate source
source disappears
source reappears
```

all converge to one deterministic catalog state.

## AC-A04 — Lifecycle

PASS when:

```text
Ready / Stale / Broken / Removed
```

have explicit transitions and none bypasses execution authority.

## AC-A05 — Search Integration

PASS when application search uses the authoritative catalog path and does not rescan discovery sources synchronously.

## AC-A06 — Recovery

PASS when corrupt catalog persistence is recoverable and previous valid state is not silently destroyed without documented reason.

Gate:

```text
G-A = PASS
```

---

# 5. P2.4-B Acceptance

## AC-B01 — Root state

PASS when roots survive:

```text
normal watching
watch failure
temporary disappearance
reappearance
```

## AC-B02 — Overflow

PASS when queue overflow produces bounded DirtyRoot recovery instead of unbounded queue growth or full-disk rebuild.

## AC-B03 — Consistency

PASS when, after quiescence:

```text
filesystem state == index state
```

for the tested root.

## AC-B04 — Generation

PASS when generation changes only after successful commit.

## AC-B05 — Health

PASS when diagnostics expose:

```text
health
generation
indexed entries
pending events
dirty roots
watcher count
last success/failure
```

Gate:

```text
G-B = PASS
```

---

# 6. P2.4-C Acceptance

## AC-C01 — Lifecycle persistence

PASS when disabled/quarantined/failure state survives restart.

## AC-C02 — Trust separation

PASS when an untrusted manifest cannot become trusted by describing itself differently.

## AC-C03 — Capability separation

PASS when:

```text
manifest request
    ≠
capability approval
```

and protected capability execution fails closed unless explicitly allowed.

## AC-C04 — Quarantine

PASS when repeated protocol failures quarantine the plugin, while business failures do not.

## AC-C05 — Recovery

PASS when a corrupt registry restores the last known-good security state when the backup is valid.

Gate:

```text
G-C = PASS
```

# 7. P2.4-D Acceptance

## AC-D01 — SDK isolation

PASS when reference plugins depend only on public SDK boundaries.

## AC-D02 — CLI lifecycle

PASS when a developer can:

```text
init
validate
build
package
install
run
inspect
uninstall
```

without directly using host internals.

## AC-D03 — Contract conformance

PASS when Rust and Python reference plugins pass the same frozen contract suite.

Gate:

```text
G-D = PASS
```

# 8. P2.4-E Acceptance

## AC-E01 — Diagnostics

PASS when timeout/crash/malformed/flood failures produce bounded structured diagnostics.

## AC-E02 — Correlation

PASS when diagnostic records can correlate:

```text
plugin_id
query_id
runtime_id
protocol_session_id
```

where applicable.

## AC-E03 — Replay

PASS when a captured safe test input can reproduce the protocol-level failure without granting new authority.

Gate:

```text
G-E = PASS
```

---

# 9. Cross-cutting acceptance

## AC-X01 — Authority

No producer except the Resolver/ActionEngine path may execute an Effect.

## AC-X02 — Identity

Candidate merging remains deterministic and source metadata is not silently lost.

## AC-X03 — Generation

Generation values represent committed data versions, not event counts or timestamps.

## AC-X04 — UI

No P2.4 task introduces blocking IO/CPU in the UI thread.

## AC-X05 — Memory

No unbounded cache, queue or process accumulation is introduced.

## AC-X06 — Plugin isolation

Plugin failure cannot crash the Launcher Core.

Gate:

```text
G-X = PASS
```

---

# 10. Performance acceptance

P2.4 must preserve 1.0 baseline unless an intentionally approved change improves the product.

Mandatory evidence:

```text
idle memory
app search
file search
startup
catalog reconcile
index maintenance
plugin lifecycle
```

Gate:

```text
G-P = PASS
```

---

# 11. Documentation acceptance

Normative docs must agree on:

```text
version
test count source
current architecture
frozen contracts
known issues
deferred items
release gate
```

No document may claim a task is complete if its Gate is not PASS.

Gate:

```text
G-R = PASS
```
