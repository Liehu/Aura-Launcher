# P2.8 Agentic Coding Specification

## 1. Agent 执行总流程

每个 P2.8 Task 必须：

```text
Inspect
  ↓
Contract Check
  ↓
Dependency Check
  ↓
Plan
  ↓
Implement
  ↓
Unit Test
  ↓
Integration Test
  ↓
Fault Test
  ↓
Security Test
  ↓
Review
  ↓
Report
```

禁止：

```text
Read Issue
→ Modify Code
→ “看起来能跑”
→ Finish
```

---

# 2. Agent 第一原则

Agent 不得擅自扩大任务范围。

例如：

```text
Task = P28-D02 Dependency Resolver
```

允许：

```text
resolver
version constraint
conflict model
tests
diagnostics
```

禁止顺便修改：

```text
installer
plugin runtime
UI
workflow
AI
```

除非任务明确授权。

---

# 3. Allowed Scope

每个 Task 必须声明：

```text
Allowed Files
Allowed Modules
Allowed APIs
Allowed Schema
```

Agent 必须先检查：

```text
git status
git diff
git log -10
```

---

# 4. Forbidden Scope

所有 P2.8 Agent 默认不得修改：

```text
frozen cross-cutting contracts
launcher-action authority boundary
workflow effect authority
AI security boundary
existing PluginId semantics
existing ExecutionId semantics
existing RuntimeId semantics
```

发现冲突：

```text
STOP
REPORT
```

不得自行重构架构。

---

# 5. Contract-First

每个实现必须先回答：

```text
Input 是什么？
Output 是什么？
State 是什么？
Authority 是什么？
Failure 是什么？
Generation 是什么？
Persistence 是什么？
Retry 是什么？
```

没有这些定义不得实现。

---

# 6. Data / Authority Boundary

Agent 必须保持：

```text
Metadata → Data
Listing → Data
Manifest → Data
TrustDecision → Data
InstallPlan → Data
DependencyResolution → Data
```

真正 Effect：

```text
Validate
→ Approve
→ launcher-action
→ Execute
```

---

# 7. Install Safety

所有 Install/Upgrade Agent 必须实现：

```text
download
verify
stage
validate
commit
```

严禁：

```text
download → overwrite
```

---

# 8. Failure Atomicity

任何状态修改都必须明确：

```text
before
during
after
rollback
recovery
```

Agent 必须测试：

```text
crash before commit
crash during commit
crash after commit
restart recovery
```

---

# 9. Dependency Resolver Agent

Resolver 必须：

```text
Pure
Deterministic
No filesystem write
No network
No install
```

同样输入必须得到相同结果。

---

# 10. Trust Agent

Trust Agent 只能产生：

```text
TrustDecision
```

不能：

```text
install
enable
execute
grant capability
```

---

# 11. Repository Agent

Repository Agent 不得：

```text
直接启动 Plugin
自动安装 Plugin
自动授予 Capability
```

---

# 12. UI Agent

UI Agent：

```text
展示状态
发出 Command
```

UI 不得：

```text
直接写 Plugin installation state
直接修改 filesystem
直接启动 plugin runtime
```

---

# 13. AI Integration

P2.7 AI：

```text
Recommendation
Proposal
```

P2.8：

```text
InstallPlan
```

两者之间必须有：

```text
Validation
```

AI 返回：

```json
{
  "plugin_id": "...",
  "version": "...",
  "reason": "...",
  "confidence": 0.92
}
```

不能直接变成：

```text
Effect
```

---

# 14. 必须测试的恶意输入

所有 Repository / Manifest / Package Agent 至少测试：

```text
invalid manifest
missing field
unknown field
duplicate dependency
dependency cycle
fake publisher
invalid signature
modified package
wrong digest
future schema
unsupported platform
incompatible launcher
malformed version
path traversal
absolute path
symlink escape
duplicate file
oversized metadata
malicious release note
```

---

# 15. Path Safety

Package 中任何文件路径必须 canonicalize。

禁止：

```text
../
..\ 
C:\
\\server\
\\?\ 
UNC
```

未经允许不得写入安装根目录之外。

---

# 16. Upgrade Agent

Upgrade 必须产生：

```text
UpgradeTransactionId
```

并保留：

```text
previous known-good version
```

禁止直接删除旧版本。

---

# 17. Rollback Agent

Rollback 必须验证：

```text
old package exists
old digest correct
old manifest valid
old compatibility valid
```

然后：

```text
stage old
→ validate
→ commit
```

---

# 18. Completion Report

所有 Agent 必须返回：

```text
Task:
Status:
Commit:

Implemented:
- ...

Tests:
- ...

Security:
- ...

Files Changed:
- ...

Contract Impact:
- none / ...

Generation Impact:
- ...

State Changes:
- ...

Known Issues:
- none / ...

Evidence:
- command
- result

Rollback:
- ...
```

---

# 19. P2.8 Agent 执行硬门槛

以下任意一个成立：

```text
signature bypass
path traversal
capability bypass
install bypass
rollback failure
transaction corruption
workflow breakage
cross-run state corruption
authority bypass
```

立即：

```text
BLOCKED
```

不得提交 COMPLETE。

---

# 21. Agent 依赖图

```text
P28-001
 ├── A
 ├── B
 └── C
      │
      ▼
      D
      │
      ▼
      E
      │
      ▼
      F
      │
      ├── G
      └── H
            │
            ▼
            I
            │
            ▼
            J
```

核心原则：

```text
Trust
Dependency
Compatibility
        ↓
InstallPlan
        ↓
Transaction
```

不能反过来。

---

# 22. Commit Policy

推荐一个 Task 一个语义提交：

```text
feat(plugin): add repository model
feat(plugin): add manifest validation
feat(plugin): add signature verification
feat(plugin): add dependency resolver
feat(plugin): add install transaction
```

禁止：

```text
p2.8 progress
misc fixes
```

这种无法审计的提交。

---

# 23. Review Agent

每个实现完成后由独立 Review Agent 检查：

```text
scope
contract
authority
state
persistence
security
rollback
tests
performance
documentation
```

Review Agent 默认：

```text
不能修改目标实现
```

只能：

```text
PASS
FAIL
BLOCKED
```
