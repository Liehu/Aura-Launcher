# P3.1 开发设计规范 — Plugin Window & Management 1.0

**状态：FROZEN DESIGN DRAFT**

---

# 1. 阶段定位

P3.1 是 P3.0（体验层）之后的第一个"管理面 + 插件窗口"阶段：

> **一个统一管理窗口（设置 / 插件 / 工作流）+ 插件独立窗口的免 hook
> 窗口管理（置顶 / 跟随钉 / 桌面钉）。**

用户决策（已确认）：
- 管理页 = **独立窗口**（uTools 模式），不进弹窗第四 Mode；
- "钉在指定应用之上"的**目标应用由用户在管理页里从正在运行的窗口中
  选择**（非插件自声明）。

# 2. 非目标

```text
不做 WebView 管理页（红线）
不做注入式 hook（DLL/SetWindowsHookEx 进他进程）
不触碰非本宿主 spawn 的进程的窗口（pid 边界硬校验）
不做插件内渲染窗口协议（RICH-RESULT 草案线，P3.x）
Marketplace 服务端（BLOCKED-EXTERNAL）
```

# 3. 架构决策

## AD-01 管理窗口（独立 Slint Window）

- `ManagementWindow`：同进程第二窗口，760×520，四 Tab：
  `General（常规）/ Plugins（插件）/ Workflows（工作流）/ About（关于）`；
- 共享 `Theme` 全局（亮/暗跟随弹窗主题）；
- 弹窗契约零语义变更；新增入口走 ADR-0019（加法性）：
  - 搜索命令 `management` / `管理`（provider_id `management`）；
  - 设置面 `settings:manage`；
  - （可选）托盘菜单项。
- 数据通道：纯投影——管理窗口不持有逻辑，回调上抛宿主
  （`management.rs`），与弹窗同模式。

## AD-02 插件启停的即时生效

- `PluginProvider::query` 从"缓存 disabled 标志"改为**每次查询读
  registry state**（SQLite PK 点查，WAL，代价可忽略）——管理页的
  启停立即生效，无需重启。

## AD-03 插件窗口发现（无 hook）

- 宿主掌握插件 pid：`ProcessSession` 暴露 `pid()`；
  `PluginHandle::pid()` 转发；
- 窗口枚举：`EnumWindows` + `GetWindowThreadProcessId` == 插件 pid 且
  `IsWindowVisible` 的顶层窗口；
- manifest 增补 `window` 声明段（`{"ui": true}`）：**声明了才枚举**，
  避免误伤无 UI 插件的终端/隐藏窗口。

## AD-04 窗口操作（全部免注入）

| 操作 | Win32 手段 | hook？ | 限制 |
|---|---|---|---|
| 置顶切换 | `SetWindowPos(HWND_TOPMOST/NOTOPMOST)` | 否 | UIPI：提权目标拒绝 |
| 钉在指定应用之上 | `SetWinEventHook(EVENT_SYSTEM_FOREGROUND)`（进程外监听）+ 前台为目标时 `SetWindowPos(HWND_INSERTAFTER, target)` | 否（事件广播≠注入） | 目标提权/UWP 时降级拒绝；目标自身改 Z 序时事件后再插一次 |
| 钉在桌面（图标层之后） | Progman `0x052C` → WorkerW 生成 → `SetParent` 挂载 | 否 | 重父化他人进程窗口：需框架兼容矩阵（tkinter/Electron/Qt）；窗口被桌面图标遮挡属预期 |

**安全红线（继承 P2.10）**：
- 枚举/操作**仅限本宿主 spawn 的插件进程**的窗口（pid 硬校验）；
- 提权目标 = 明确报错拒绝，不静默降级；
- 目标应用选择列表 = 用户从**正在运行的窗口**里选（`EnumWindows`
  可见、有标题的顶层窗口，排除自身/工具窗口）。

## AD-05 钉住目标的选定与生命周期

- 管理页"窗口"列表实时枚举运行中窗口（标题 + pid）；
- 选定后记录 `(plugin_window_hwnd, target_hwnd)`；目标窗口销毁
  （`IsWindow` 失败）→ 自动解除跟随并提示；
- 解除钉住 = 恢复 `HWND_NOTOPMOST` / `SetParent(NULL)`（可还原）。
