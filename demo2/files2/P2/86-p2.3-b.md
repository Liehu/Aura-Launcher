# P2.3-B — End-to-End Product Closure

P2.3-A 已经把**架构、身份、Generation、权限边界和持久化契约**冻结下来。现在进入 B，目标从“架构正确”切换为：

> **证明用户从启动 Launcher 到完成一次真实任务的完整产品链路可以闭环。**

这一批仍然**不新增产品能力**。重点是跨 crate、跨进程、跨状态的真实 E2E。

---

# 1. P2.3-B 批次边界

```text
P2.3-B
│
├─ B1 Launcher Startup → Search
├─ B2 Application Search → Launch
├─ B3 File / Folder Search → Open
├─ B4 Plugin Search → Execute
├─ B5 MCP Search → Execute
├─ B6 Workflow → Multi-step Execution
├─ B7 Context + Ranking + Cache
├─ B8 Favorites + Usage + Ranking

└─ B11 Product Golden Path Suite
```

最终形成：

```text
P2.3-B
    ↓
Golden E2E Suite

P2.3-C Reliability / Recovery Closure
```

# 2. E2E 测试原则

## 2.1 测试产品链路，而不是测试内部函数

例如不要把：

```text
ActionResolver::resolve()
ActionEngine::execute()
```

各测一遍就宣布 Launch E2E 完成。

真正的 E2E 应该是：

```text
Hotkey
  ↓
Launcher Popup
  ↓
Query
  ↓
SearchCoordinator
  ↓
Provider
  ↓
Candidate Merge
  ↓
Ranking
  ↓
Selection
  ↓
Action Resolution
  ↓
validate()
  ↓
execute()
  ↓
Effect
  ↓
OS / Plugin / MCP
  ↓
Usage State
  ↓
Next Search
```

内部 unit test 继续存在，但 P2.3-B 的验收对象是整条链。

# 3. B1 — Launcher Startup → Search

## Scenario

```text
Launcher cold start
    ↓
Config loaded
    ↓
DB opened
    ↓
Index available
    ↓
Providers registered
    ↓
Hotkey registered
    ↓
Popup opened
    ↓
Query entered
    ↓
Results displayed
```

验证：

* 启动不存在 provider 初始化竞争；
* Index rebuild 后台化后不会出现 search race；
* Popup 打开后第一条 SearchRequest 能正确取得 context；
* Provider failure 不影响其他 provider；
* Search 完成后 UI 收到正确 snapshot。

### 必须覆盖

```text
cold start
warm start
existing index
index rebuilding
provider unavailable
empty query
non-empty query
```

# 15. Test Isolation

E2E 不允许污染开发环境。

使用专门：

```text
E2E_TEMP_ROOT
E2E_CONFIG_ROOT
E2E_DATA_ROOT
E2E_CACHE_ROOT
```

例如：

```text
%TEMP%\launcher-e2e\<run-id>\
```

每次：

```text
setup
 ↓
test
 ↓
assert
 ↓
cleanup
```

不得依赖：

```text
真实用户 Favorites
真实用户 History
真实 Application Catalog
真实 Plugin Registry
```

# 16. E2E Determinism

E2E 最危险的问题不是失败，而是：

```text
偶尔失败
```

因此必须固定：

```text
Clock
Random seed
Fixture data
Provider ordering
Plugin manifest ordering
MCP server behavior
Temporary paths
```

Ranking 测试尤其不能依赖机器上真实安装的软件数量。

# 19. P2.3-B 完成后的项目状态

此时项目会从：

```text

```

```text

```

```text

        ✅
        ↓

        ✅
        ↓
```

因此 **P2.3-B 不应该加入新的功能需求**。它的主要价值是把现在分散在 `launcher-core / search / action / plugin / mcp / workflow / runtime / ui` 中已经通过单元测试证明的能力，第一次用**真实产品路径**串起来。

建议按：

```text
B1 Startup → Search
        ↓
B2 Application Launch
        ↓
B3 File / Folder
        ↓
B4 Plugin
        ↓
B5 MCP
        ↓
B6 Workflow
        ↓
B7 Cache / Context / Generation
        ↓
B8 Favorites / Usage / Ranking
        ↓
B9 Failure Isolation
        ↓
B10 Cross-feature Session
        ↓
B11 Golden Path Suite
```

推进。

其中 **B2、B4、B5、B7** 是 P2.3-B 的四个关键验收点：分别覆盖 ActionEngine 主链、Plugin 执行链、MCP Runtime 链，以及 P2.2-F 刚刚修复的 **Cache + Generation 一致性链**。
