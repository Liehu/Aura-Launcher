# P2.3-G — Installer / Upgrade / Migration QA

进入 **P2.3-G**。

这一批的定位不是继续开发安装器，而是对 **P2.2-E 已形成的 Installer / Upgrade / Recovery 主体**进行最终产品生命周期验收：

> **从全新安装，到产生用户数据，再升级、迁移、异常中断、修复、卸载、重新安装，整个生命周期都不能破坏用户数据、越过版本迁移边界或留下不可恢复状态。**

# 3. 用户数据与程序数据必须分离

最终必须满足：

```text id="h8n2sb"

   ↓
程序文件替换
   ↓
用户数据保留
```

而不是：

```text id="zv0k5f"
Upgrade
   ↓
delete install directory
   ↓
recreate everything
```

特别保护：

```text id="qd9a27"
Favorites
Usage / History
Application Catalog
File Index
Plugin Registry
Config
```

具体哪些可重建、哪些必须迁移，要以 P2.3-A 的 Persistence Inventory 为准。

# 10. G6 — Database Migration

这部分是 G 的核心。

每一个 persistent database 都必须有：

```text id="n3zj1a"
schema_version
migration path
failure behavior
backup policy
```

例如：

```text id="9tqj1q"
v1
 ↓
migration
 ↓
v2
```

不能：

```text id="icx3h9"
v1 DB
→ open with v2
→ hope it works
```

---

# 11. Migration Atomicity

迁移必须满足：

```text id="o9hh5m"
Migration Start
 ↓
transaction/journal
 ↓
success
 ↓
commit
```

失败：

```text id="5kg45r"
Migration failure
 ↓
rollback/recovery
```

不能留下：

```text id="8jv61g"
half-v1
half-v2
```

的不可判定状态。

---

# 12. G7 — Config Migration

Config 和 DB 不完全相同。

测试：

```text id="c9bhjo"
old config
 ↓
new version
 ↓
migration
```

例如：

```text id="7fdhqp"
renamed field
removed field
new default
enum evolution
```

必须明确：

```text id="p1l8ic"
Preserve
Transform
Default
Ignore
Reject
```

而不是简单“未知字段都删掉”。

# 20. G13 — Uninstall / Reinstall

必须明确卸载语义：

```text id="n5q2lm"

```

与：

```text id="ry0ujm"

```

是否是一个操作。


# 27. 数据一致性断言

每一次 Upgrade 前建立：

```text id="xqbz9s"
DataSnapshot A
```

升级后：

```text id="2x4kyp"
DataSnapshot B
```

然后比较：

```text id="6a8hjc"
Favorites
History
Config semantic state
Plugin registrations
Catalog identity
Index integrity
```

不要简单比较 DB binary，因为 migration 本身可能合法改变：

```text id="g9h8g7"
schema
indexes
metadata
```

应该比较**语义内容**。

---

# 28. Upgrade 必须验证 Generation

升级后不能只验证数据。

还要验证：

```text id="9q2y0n"
FileGeneration
ApplicationCatalogGeneration
UserStateGeneration
ContextGeneration
RankingGeneration
Provider/Lifecycle generation
```

其中：

* 保留的 UserState 必须保持语义；
* Rebuild 的 derived state 必须生成新的 generation；
* 无意义的数据恢复不能产生错误的 generation；
* Cache 必须在不兼容情况下失效。

---

# 29. G 的最高风险项

按照目前架构，我会把以下四项列为 **Release Blocker**：

### ① Migration 非原子

```text id="eq6gny"
partial migration
```

可能直接造成用户数据损失。

### ② Upgrade 删除 User Data

```text id="tm0i2d"
installer cleanup
```

误删 Favorites / History / Plugin Registry。

### ③ Interrupted Upgrade 后假正常

```text id="j2wvk7"
half upgraded
→ launcher reports Healthy
```

这是非常危险的状态。

### ④ Migration 失败后空库重建

```text id="5l48xo"
old DB corrupt/failure
→ delete
→ create new
```

必须禁止未经明确用户选择的这种行为。
