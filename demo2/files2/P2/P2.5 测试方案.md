# Aura Launcher P2.5 测试方案

## 1. 测试目标

P2.5 的测试重点从单纯的：

```text
功能可用
```

升级为：

```text
Correctness
Determinism
Concurrency Isolation
Cancellation
Retrieval Quality
Ranking Quality
Explainability
Recovery
Performance
Regression
```

---

# 2. Query Intelligence

必须覆盖：

## Normalization

- 空查询
- 多空格
- 中英文
- Unicode
- path
- wildcard
- quote

## Intent

```text
Application
File
Folder
Command
Plugin
Workflow
Mixed
Unknown
```

## Filter

```text
app:chrome
file:pdf
folder:project
cmd:ipconfig
wf:backup
plugin:calculator
```

未知 prefix 必须 safe fallback。

---

# 4. Coordinator

## Normal

全部 Provider 返回：

```text
Complete
```

## Slow

一个 Provider 超时：

```text
其他 Provider 正常返回
Core 不阻塞
结果允许 Partial
```

## Crash

一个 Provider crash：

```text
Core alive
other providers unaffected
```

## Supersede

连续：

```text
c
ch
chr
chro
chrome
```

必须保证：

```text
latest request wins
```

---

# 5. Determinism

同一输入执行：

```text
>= 1000 次
```

必须保证：

- candidate set 一致
- identity 一致
- score 一致
- order 一致
- explanation 一致

另外必须随机打乱 Provider completion order，再验证最终结果完全相同。

---

# 6. Concurrency Stress

场景：

```text
100 providers
1000 queries
```

验证：

```text
max_in_flight
task cleanup
no deadlock
no starvation
memory bounded
```

必须证明：

```text
max_in_flight <= configured_limit
```

---

# 7. Partial Result

必须测试：

```text
Complete
Partial
TimedOut
Cancelled
Failed
```

重点：

```text
Partial != NoResult
```

UI 不得把 Partial 显示成：

```text
No results
```

# 9. Ranking

固定验证：

```text
exact > prefix > contains > fuzzy
```

还要验证：

```text
intent
pinyin
history
recency
context
provider_hint
```

```text
boost never creates candidate
```

---

# 10. Explainability

必须验证：

```text
sum(score_parts) == total
```

允许浮点 epsilon。

同时：

- merge 不丢 evidence
- dropped candidate 的 metadata 正确保留
- explanation 不改变 identity
- explanation 不授予 capability
- explanation 不触发 Effect

---

# 11. Fault Injection

至少 10 类：

1. Provider timeout
2. Provider crash
3. malformed provider result
4. result flood
5. provider restart
6. DB lock
7. DB corruption
8. FTS rebuild failure
9. supersede race
10. cancellation race

安全结果：

```text
S0 = 0
S1 = 0
S2 = 0
```

# 18. Hard Regression

以下任何一项失败立即 BLOCK：

- `exact > prefix > contains > fuzzy` 被破坏
- Provider completion order 影响结果
- timeout 阻塞其他 Provider
- superseded request 覆盖 latest UI
- FTS migration 丢数据
- FTS failure 无 fallback
- explanation 与 score 不一致
- Search 绕过 Action authority
- RSS > 80MB
- performance budget fail
- S0/S1/S2 > 0
