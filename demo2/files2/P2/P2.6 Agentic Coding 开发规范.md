# Aura Launcher P2.6 Agentic Coding Specification

## 1. 核心原则

P2.6 是一个比 P2.5 更容易被 Agent 做乱的阶段。

原因是 Workflow 同时涉及：

```text
Graph
State Machine
Persistence
Concurrency
Recovery
Human Events
UI
```

因此必须坚持：

```text
Contract
→ State Machine
→ Persistence
→ Runtime
→ UI
```

而不能：

```text
UI
→ 临时状态
→ Runtime
→ 再补 Contract
```

# 3. 第一原则：先解决 v0.1/v2 漂移

如果 Agent 发现代码已经存在：

```text
v2 graph
condition
variables
transition
```

不得直接继续扩展。

必须先确认：

```text
现有代码
vs
WORKFLOW-CONTRACT-v0.1
vs
P2.6 Contract v2
```

如果冲突：

```text
BLOCKED
```

或由 P26-001 正式收敛。

---

# 4. 一 Task 一 PR

```text
1 Task
1 branch
1 PR
```

不得同时实现：

```text
DAG
+
Durable
+
Approval
+
Editor
```

---

# 5. Workflow Authority Redline

唯一 Effect path：

```text
Workflow
 ↓
ReferenceResolver
 ↓
ActionResolver
 ↓
launcher-action::validate()
 ↓
launcher-action::execute()
 ↓
Effect
```

Workflow Runner 本身：

```text
NO EFFECT AUTHORITY
```

---

# 6. Definition / Run 分离

严格保持：

```text
WorkflowDefinition
≠
WorkflowRun
≠
ResolvedAction
≠
Effect
```

Definition：

```text
logical plan
```

Run：

```text
state
```

ResolvedAction：

```text
ephemeral
```

Effect：

```text
external side effect
```

---

# 7. Durable State Rule

持久化任何 state 前必须回答：

```text
谁拥有？
何时提交？
何时递增？
崩溃后如何恢复？
是否可能重复？
是否需要 re-resolve？
```

不得直接：

```text
serialize struct
→ assume durable
```

---

# 8. Checkpoint Rule

Checkpoint 只记录：

```text
committed state
```

不能记录：

```text
in-progress mutable state
```

不能保存：

```text
ResolvedAction
Effect handle
live process handle
capability grant
confirmed=true
```

---

# 9. Recovery Rule

永远不要：

```text
Executing
→ process died
→ automatically retry
```

必须先分类：

```text
Before execution
During resolution
Before validation
After validation
During effect
After effect but before checkpoint
```

然后按 policy 决定：

```text
Retry
Skip
ReResolve
Stop
```

---

# 10. DAG Rule

Graph validator 是 runtime 前置门。

必须先：

```text
validate graph
```

再：

```text
schedule
```

禁止 Scheduler 自己修复非法图。

---

# 11. DAG Invariants

必须测试：

```text
unique node ids
valid entry
no dangling edges
all reachable or explicitly excluded
acyclic
valid joins
bounded nodes
```

---

# 12. Condition Rule

Condition engine 必须：

- deterministic
- pure
- bounded
- side-effect free

禁止：

```text
condition → filesystem mutation
condition → network call
condition → execute Action
```

---

# 13. Variable Rule

变量必须明确 scope：

```text
WorkflowRun scoped
```

禁止默认：

```text
global variable
```

并发 branch 修改同一 variable 时必须有明确 semantics。

第一版推荐：

> branch writes 必须隔离，Join 时进行显式 merge。

禁止隐式 last-writer-wins。

---

# 14. Parallelism Rule

必须 bounded：

```text
max_parallel_nodes
max_active_runs
max_queue_depth
```

禁止：

```text
spawn all ready nodes
```

---

# 15. Approval Rule

Approval 是：

```text
event
```

不是：

```text
authorization state
```

Approval 必须绑定：

```text
run
node
approval_id
origin session
```

禁止跨 Run replay。

---

# 16. Trigger Rule

Trigger 只能创建：

```text
WorkflowRunRequest
```

不能：

```text
Trigger → ActionEngine
```

---

# 17. Editor Rule

Visual Editor 只能修改：

```text
WorkflowDefinition Draft
```

不能修改：

```text
WorkflowRun
```

不得：

```text
drag node
→ execute node
```

---

# 18. Version Rule

正在运行的：

```text
Definition v1
```

永远继续引用：

```text
v1
```

即使当前编辑器已经保存：

```text
v2
```

---

# 19. Testing Rule

每个 runtime Task 至少：

```text
unit
integration
failure path
recovery path
```

所有 state transition 必须至少有：

```text
valid transition
invalid transition
restart transition
```

# 21. BLOCKED Conditions

出现以下任意项必须停止：

- Workflow Contract 冲突
- Durable semantics 未定义
- recovery semantics 不明确
- checkpoint 可能保存 ResolvedAction
- approval 可以跨 Run replay
- parallelism 无界
- variable merge 未定义
- DAG cycle 语义不明确
- Trigger 需要直接执行 Action
- Editor 需要访问 runtime authority
- 任务已经进入 Agent Runtime / P2.7 范围
