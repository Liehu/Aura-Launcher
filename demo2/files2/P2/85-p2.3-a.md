# P2.3-A — Architecture & Contract Closure

**状态：进入实施**

本批次的目标不是重构架构，而是把 P0～P2.2 已经形成的设计与实现，收口为一套可以作为 **Launcher 1.0 冻结基线** 的架构契约。

# P2.3-A — Architecture & Contract Closure v1.0

## 1. Batch Definition

### 1.1 Objective

完成 Launcher 1.0 发布前的架构与契约最终审计，确认：

1. crate 边界没有越界；
2. Action → Effect 执行链没有旁路；
3. Execution / Runtime / Protocol Session 身份没有混用；
4. 所有 Search Cache Generation 的来源、递增与失效语义一致；
5. Security Invariants 在实现中可验证；
6. Persistence / Migration 边界明确；
7. 已完成能力与未完成能力没有文档状态漂移；
8. 形成 Launcher 1.0 Frozen Contract Index。

### 1.2 Non-Goals

本批次禁止：

* 新增用户功能；
* 修改既有产品交互；
* 新增新的 Effect Executor；
* 新增 Core-level ActionEngine；
* 重写现有 Search / Action / Plugin / MCP Runtime；
* 提前实现 Agent Confirmation；
* 提前实现 Durable Workflow；
* 提前实现 Cloud / Marketplace；
* 因“代码看起来可以更优雅”而进行架构重构。

只有在发现**契约违规、权限旁路、状态代际错误、数据一致性问题或明确的 1.0 发布阻断缺陷**时才允许修改代码。

# 4. P2.3-A-02 — Execution / Effect Lineage Audit

## 4.1 Frozen Execution Chain

Launcher 1.0 的执行权路径冻结为：

```text
Producer
    │
    ├─ Search
    ├─ Workflow
    ├─ AI / Agent
    └─ UI
    │
    ▼
Resolved Action
    │
    ▼
launcher-action
 ├─ validate()
 └─ execute()
    │
    ▼
Effect
    │
    ▼
Effect Executor
 ├─ System
 ├─ PluginBroker
 └─ McpExecutor
```

其中：

> `launcher-action` crate 即 ActionEngine。

不得新增：

```text
CoreActionEngine
UiActionEngine
PluginActionEngine
McpActionEngine
```

等第二执行网关。

---

## 4.2 Producer Rule

所有 Producer 只能产生：

```text
Command
ActionDescriptor
ActionProposal
Workflow Reference
```

不得产生：

```text
ResolvedAction
CapabilityGrant
Effect
ExecutionId owned by downstream
```

特别是 AI / Agent：

```text
Planner
   ↓
Proposal
   ↓
Host
   ↓
Resolver
   ↓
ActionEngine
```

而不是：

```text
Planner
   ↓
Effect
```

---

## 4.3 Resolver Rule

ActionResolver 唯一职责：

```text
ActionDescriptor
+
Current Context
+
Capability State
+
Policy
        ↓
ResolvedAction / Disabled / Hidden / Invalid
```

Resolver 不执行 Effect。

---

## 4.4 Effect Rule

只有经过：

```text
validate()
→ execute()
```

的 Action 才能进入 Effect execution path。

任何以下对象均不得直接进入 Executor：

```text
SearchCandidate
ActionProposal
ActionDescriptor
WorkflowAction
AI Plan
UI Command
```

# 5. Execution Identity

## 5.1 ExecutionId

定义：

> 一个实际执行尝试对应一个唯一 ExecutionId。

因此：

```text
original attempt → E1
retry             → E2
replan            → E3
```

同一次 attempt 在下游不得重新生成：

```text
E1 → Plugin → new plugin ExecutionId ❌
```

而必须：

```text
Core E1
  ↓
Plugin E1
  ↓
Host E1
```

---

# 6. Runtime Identity

以下三个 ID 永远不同义：

```text
RuntimeId
ProtocolSessionId
ExecutionId
```

### RuntimeId

表示：

```text
一个长期或短期进程运行实例
```

### ProtocolSessionId

表示：

```text
一个 MCP protocol session
```

### ExecutionId

表示：

```text
一次实际执行 attempt
```

禁止：

```text
RuntimeId == ExecutionId
ProtocolSessionId == ExecutionId
```

---

# 7. Retry / Replan Contract

## Retry

Retry 是：

```text
same logical step
new execution attempt
new ExecutionId
```

## Replan

Replan 是：

```text
new observation
new planner decision
new proposal
new execution
new ExecutionId
```

因此：

```text
Retry ≠ Replan
```

两者不得通过复用旧 ExecutionId 来实现。

# 8. P2.3-A-03 — State Generation Matrix v1.0

Launcher 1.0 冻结以下状态代际：

| Generation                    | Owner                        | Meaning                | Cache Impact |
| ----------------------------- | ---------------------------- | ---------------------- | ------------ |
| FileGeneration                | File Index                   | 文件索引状态                 | ✅            |
| ApplicationCatalogGeneration  | Application Catalog          | Application Catalog 状态 | ✅            |
| UserStateGeneration           | Favorite / History           | 用户状态                   | ✅            |
| ContextGeneration             | Runtime Context              | 当前语义上下文                | ✅            |
| RankingGeneration             | Ranking Config               | Ranking 算法/权重状态        | ✅            |
| Provider/Lifecycle Generation | Provider / Plugin visibility | Provider 可见候选集变化       | ✅            |

---

## 8.1 Generation Rule

Generation 只有在**语义状态真正发生变化**时递增。

例如：

```text
set_context(A)
set_context(A)
```

不得：

```text
generation: 10 → 11 → 12
```

正确：

```text
generation: 10 → 10
```

而：

```text
set_context(A)
set_context(B)
```

才：

```text
generation: 10 → 11
```

---

## 8.2 ContextGeneration

当前交互模型：

```text
Popup opened
  ↓
Launcher owns foreground
  ↓
search requests
```

因此 popup 生命周期捕获与 request-time 语义等价。

但真正冻结的是：

> ContextGeneration 由 Context Semantic State 的 equality 决定，而不是由 capture 次数决定。

---

## 8.3 CacheKey

Launcher 1.0 CacheKey 必须至少包含：

```text
normalized_query
file_generation
application_generation
user_state_generation
context_generation
ranking_generation
```

如 Provider 生命周期已经纳入统一 generation，则同时纳入对应 generation。

Cache hit：

```text
Cache lookup
 ↓
Hit
 ↓
Return
```

不得执行：

```text
Provider dispatch
```

Cache hit 的执行行为仍然必须是：

```text
Cached Command / ActionDescriptor
 ↓
ActionResolver
 ↓
validate()
 ↓
execute()
```

Cache 不得保存：

```text
ResolvedAction
ExecutionId
Effect
```

---

# 9. Cache Invalidation Contract

建立单一判定原则：

> 任何可能改变“相同 Query 应返回哪些候选、以什么排序返回”的状态，都必须影响 Cache Key 或显式使 Cache 失效。

因此：

```text
File index change          → FileGeneration
Application Catalog change → ApplicationGeneration
Favorite / History change  → UserStateGeneration
Context change             → ContextGeneration
Ranking config change      → RankingGeneration
Plugin visibility change   → Provider/Lifecycle generation
```

禁止依赖：

```text
“反正过 TTL 就会失效”
```

来解决语义一致性问题。

TTL 是性能策略，不是 correctness 机制。

# 10. P2.3-A-04 — Security Invariant Catalog

冻结现有授权与执行不变量。

## INV-AUTH

### INV-AUTH-001

未通过 ActionResolver 的对象不得进入执行层。

### INV-AUTH-002

外部 / Plugin / MCP / AI metadata 不得增加 capability。

### INV-AUTH-003

Execution identity 必须贯穿一次执行 attempt。

### INV-AUTH-004

Confirmation 不得授权 stale 或 replaced action。

### INV-AUTH-005

Disabled / Hidden / Invalid action 不得进入 execute。

### INV-AUTH-006

Protocol failure 不得静默映射为 success。

---

## INV-RUNTIME

### INV-RUNTIME-001

Runtime persistence 不得增加 execution authority。

### INV-RUNTIME-002

Runtime recovery 不得自动 replay failed execution。

### INV-RUNTIME-003

RuntimeId 不得作为 ExecutionId 使用。

### INV-RUNTIME-004

同一 protocol runtime 中 protocol operation 必须串行化。

### INV-RUNTIME-005

Runtime cleanup 必须覆盖其进程树。

---

## INV-MCP-SESSION

冻结：

```text
ProtocolSessionId
RuntimeId
ExecutionId
```

三者独立。

Session Invalid 后：

```text
new session
new execution
```

不得：

```text
replay failed request
```

并确认：

```text
business error
→ session remains usable

protocol violation
→ invalidate

timeout / process crash
→ invalidate + runtime recovery
```

---

## INV-CONTEXT

### INV-CONTEXT-004

ContextGeneration 仅在 Context Semantic State 实际发生变化时递增。

因此：

```text
same semantic state
→ same generation
```
