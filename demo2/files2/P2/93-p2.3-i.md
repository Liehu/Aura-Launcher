# P2.3-I — Release Candidate

进入 **P2.3-I**。

这是 P2.3 的最后一个小批次。与前面的 A～H 不同，I 不再承担架构设计、功能开发或大规模 QA。

> **I 的唯一目标：把已经验证完成的 Launcher 1.0 变成一个可正式交付的 Release Candidate。**

核心原则：

```text id="x0b42f"
功能冻结
契约冻结
测试冻结
版本冻结
        ↓
只允许 Release-blocking 修复
        ↓
RC
```

---

# 1. P2.3-I 范围

```text id="4f33mn"
P2.3-I Release Candidate
│
├─ I1 Feature Freeze
├─ I2 Version Freeze
├─ I3 RC Build
├─ I4 Full Release Gate
├─ I5 Release-blocking Fix
├─ I6 Rebuild / Re-test
├─ I7 Artifact Verification
├─ I8 RC Evidence Package
├─ I9 RC Acceptance
└─ I10 Launcher 1.0 Release Decision
```

---

# 2. I1 — Feature Freeze

进入 I 以后：

## 禁止

```text id="l1c2kv"
新增功能
修改产品交互
新增 Provider
新增 Action
新增 Effect
新增 Workflow capability
新增 Agent capability
新增 MCP feature
新增 Plugin feature
新增 UI mode
```

包括：

> “顺手重构一下以后会更好”。

全部禁止。

---

## 允许

只允许以下类型修改：

```text id="8k45bh"
P0/P1 Bug
Security Fix
Data-loss Fix
Crash Fix
Release-blocking Performance Fix
Release-blocking Installer Fix
Release-blocking UI Fix
Packaging Fix
Documentation Fix
```

如果一个问题需要修改架构契约：

```text id="kk7jv5"
P2.3-I
   ↓
STOP
   ↓
return to A
```

不能偷偷在 RC 阶段改。

---

# 3. I2 — Version Freeze

正式确定：

```text id="xyd6lp"
Product = Launcher
Version = 1.0.0-rc1
```

所有位置必须一致：

```text id="r66x4c"
Cargo
Installer
Package
Executable metadata
UI About
Release Manifest
Artifact name
```

例如：

```text id="3mvbxr"
launcher-1.0.0-rc1
```

---

# 4. RC Tag

建立 immutable tag：

```text id="h5f0e2"
v1.0.0-rc1
```

Tag 对应：

```text id="m4ul8e"
commit SHA
```

之后：

> RC artifact 必须始终能够反向定位到这个 commit。

Tag 后禁止直接修改。

发现问题：

```text id="2rd9rs"
fix commit
 ↓
v1.0.0-rc2
```

不要：

```text id="a9eqim"
overwrite rc1
```

---

# 5. I3 — RC Build

执行 H 阶段冻结的唯一 Release Pipeline：

```text id="j4l9wb"
Tag
 ↓
Clean checkout
 ↓
Clean build
 ↓
Release profile
 ↓
Generate artifact
```

必须从：

```text id="62vqpy"
clean workspace
```

开始。

不能依赖开发机残留：

```text id="u6jrh0"
target/
cache/
local config
local plugins
```

# 6. I4 — Full Release Gate

RC 必须执行完整：

```text id="a4ahmw"
G01 Format / Static
G02 Build / Warnings
G03 Unit / Integration
G04 Architecture / Topology
G05 Product E2E
G06 Security
G07 Performance
G08 Memory / Soak
G09 Visual Regression
G10 Installer / Upgrade / Recovery
G11 Package Integrity / Signing
G12 Release Manifest / Evidence
```

要求：

```text id="f7xs2n"
12 / 12 PASS
```

---

# 7. Gate 不允许“软通过”

RC 中：

```text id="edx0iz"
FAIL     → FAIL
SKIPPED  → not PASS
BLOCKED  → FAIL
WARN     → according to frozen policy
```

不能：

```text id="j1xq4q"
“这个 CI 环境刚好不能跑，所以手工确认”
```

替代 Release Gate。

---

# 8. I5 — Release-blocking Fix

完整 Gate 如果失败：

```text id="c6miqs"
FAIL
 ↓
classify
```

### Blocker

```text id="k4mg9a"
P0
P1
security
data loss
crash
installer corruption
signature
authority bypass
```

必须修。

### Non-blocker

例如：

```text id="9bw8rz"
minor diagnostic wording
non-critical benchmark noise
documentation typo
```

按照既定政策决定是否进入 RC。

---

# 9. RC Bug Fix Rules

每一次 RC 修复必须记录：

```text id="mm1ghj"
RC defect
root cause
affected contract
fix
test added
regression risk
gate rerun
```

禁止：

```text id="b3p1wk"
fix code
→ “本地跑过”
→ continue
```

---

# 10. I6 — Rebuild / Re-test

任何：

```text id="n9x3gn"
code change
installer change
configuration change
dependency change
build configuration change
```

都必须重新执行相关 Gate。

如果改变：

```text id="kj2qyn"
Action
Search
Runtime
MCP
Plugin
Persistence
```

直接重新执行完整 Gate。

# 11. Dependency Change

尤其严格处理：

```text id="z0o1t8"

```

# 13. RC Smoke Test

完整 Gate 后再做一次最小人工/自动 Smoke：

```text id="pq8o31"
Install
 ↓
Launch
 ↓
Hotkey
 ↓
"notepad"
 ↓
Enter
 ↓
application launches
 ↓
exit
```

以及：

```text id="zg6d1n"
file search
plugin
MCP
workflow
```

各一条最核心路径。

这里的 Smoke **不是代替 E2E**。

它用于确认：

> 最终打包出来的 artifact 在真实安装环境中还能启动。

# 25. P2.3 之后

这里我建议**不要马上进入 P3**。

先经历一个很短但必要的：

## P2.4 — 1.0 Stabilization

定位：

> **真实使用反馈驱动的稳定性维护，不再增加产品方向性功能。**

只允许：

```text
Crash Fix
Regression Fix
Security Fix
Performance Regression Fix
Compatibility Fix
Migration Fix
Installer Fix
```

经过这个稳定阶段后，再正式：

```text
Launcher 1.0.0
        ↓
P3 Product Evolution
```

而 P3 再开始之前，就可以重新定义下一代能力优先级：

```text
P3-A Search Intelligence
P3-B AI / Agent
P3-C Workflow 2.0
P3-D Plugin Ecosystem 2.0
```

**所以现在 P2.3-I 的真正终点不是“代码完成”，而是拿到一个可以被视为真实产品候选版本的 `1.0.0-rc1`。** 一旦 RC Gate 全绿，下一阶段就不应该继续往 1.0 里塞功能。
