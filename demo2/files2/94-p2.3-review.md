# 五、Plugin Ecosystem：Registry 已经补上，但有一个值得复查的问题

你现在已经拥有：

```text
plugins.db
enabled
quarantined
failures
plugin_capabilities
```

并支持：

```text
restart
→ state restored
```

这是明显的进步。

但是这里有一个我建议在正式 1.0 前重新审查的点：

> **`plugins.db` 损坏后，“所有插件默认 enabled”是否真的属于安全默认值。**

文档把它定义成：

```text
plugins.db corrupt
→ rebuild
→ all plugins default enabled
```

这对“恢复可用性”是友好的，但对安全性未必是最保守策略。

因为假设用户此前：

```text
Plugin A = disabled
Plugin B = quarantined
```

Registry 损坏后如果统一恢复：

```text
enabled = true
```

那么**此前用户做出的安全/信任选择会丢失**。

虽然：

```text
capability decision = unset → denied
```

可以限制 capability，但：

> “disabled/quarantined state 被清掉以后插件重新进入候选集”

本身就值得作为一个 1.0 安全语义重新确认。

我建议最终策略至少区分：

```text
known plugin
previously trusted
previously disabled
previously quarantined
new/unknown plugin
```

这一点当前记录里还没有被完全闭环。

因此：

**Plugin Registry = ✅**

**Plugin Recovery Security Semantics = ⚠️**
