# MVP4.3 Phase 12 — Release Gate

Phase 12 应严格定义为：

> **Release Candidate 验收与封版，不再改变 MCP/Core/Workflow/AI 架构。**

截至 Phase 11，你已经有：

```text id="mvp43-current"
346 tests
├── Functional
├── Workflow
├── AI
├── Security
└── Compatibility

cargo build --workspace
    → zero warnings

check_topology.py
    → PASS
    → 15 crates / 8 apps
```

因此 Phase 12 的工作不是“再实现一个功能”，而是把这些分散的验证正式收敛成 **一个可重复、可审计、可发布的 Release Gate**。

---

# 1. Release Gate 总览

建议最终闸门分成 8 个维度：

```text id="release-gate"
                    MVP4.3 RC
                        │
       ┌────────────────┼─────────────────┐
       │                │                 │
   Functional        Security        Compatibility
       │                │                 │
       ├────────────────┼─────────────────┤
       │                │                 │

       │                │                 │
       └────────────────┼─────────────────┘
                        │
                Reproducibility
                        │
                  Documentation
                        │
                        ▼
                  RELEASE / BLOCK
```

Release 不是：

```text

```

而是：

```text
所有 required gate = PASS
任何 blocking issue = 0
```

# 15. Configuration Compatibility

Release 时必须验证默认配置。

至少：

```toml id="config"
[mcp]

[[mcp.servers]]
```

以及：

```text
没有 mcp 配置
```

情况下：

```text
Launcher
→ 正常启动
→ 正常搜索
→ 正常 UI
```

即：

> MCP 是 optional capability，不得成为 Launcher 启动依赖。

再验证：

```text
broken MCP server config
```

结果应该是：

```text
Launcher still starts
MCP provider reports availability error
Other providers remain functional
```

这是非常重要的 failure containment。

# 22. Gate Severity

建议正式规定：

| 状态                        | Release                              |
| ------------------------- | ------------------------------------ |
| S0/S1/S2 security failure | ❌ Block                              |
| Architecture violation    | ❌ Block                              |
| Functional regression     | ❌ Block                              |
| Protocol regression       | ❌ Block                              |
| Topology failure          | ❌ Block                              |
| Zero-warning violation    | ❌ Block                              |
| Visual regression         | ❌ Block                              |
| Performance regression    | ❌ Block / review by frozen threshold |
| Documentation typo        | 🟡 Fix before final                  |
| Deferred feature          | ✅ Allowed if documented              |

这样不会出现：

> “功能都好了，这个安全测试先忽略。”

### 最终建议

Phase 12 **不要再新增测试类别、不要再增加 MCP capability、不要再改 Action/Workflow API**。现在最有价值的是把现有 346 tests、Security Matrix、Compatibility Matrix、10 张视觉基线、Topology 和 Benchmark **统一编排成一个可重复的 `release-gate` 命令及一份机器可读 Release Manifest**。

这样 MVP4.3 最终交付的就不只是：

> “346 个测试通过”

而是：

> **一个已经经过功能、架构、安全、兼容性、视觉、性能和可复现性七重验证的 Release Candidate。**

完成这一阶段后，MVP4.3 的新增架构工作应正式停止，后续需求进入 **MVP4.4 / v0.2 backlog**。
