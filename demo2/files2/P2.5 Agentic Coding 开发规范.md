# Aura Launcher P2.5 Agentic Coding 开发规范

## 1. 基本原则

P2.5 使用 Agentic Coding 时，Agent 不是自由重构者，而是：

> 在已冻结架构、契约和测试门禁下执行一个明确 Task。

标准流程：

```text
Inspect
→ Contract Check
→ Plan
→ Implement
→ Test
→ Benchmark
→ Review
→ Report
```

---

# 2. Agent 必读顺序

每个 Agent 启动任务以后必须读取：

```text
demo2/native-launcher/AGENTS.md

demo2/native-launcher/docs/ARCHITECTURE.md

demo2/native-launcher/docs/INVARIANTS.md

demo2/native-launcher/docs/P2-CROSS-CUTTING-CONTRACTS.md

demo2/native-launcher/docs/COMMAND-CONTRACT-v0.1.md

demo2/native-launcher/docs/ACTION-CONTRACT-v0.1.md

demo2/native-launcher/docs/TESTING.md

当前 P2.5 Task Spec
```

---

# 3. 一 Task 一 PR

推荐：

```text
1 Task
1 branch
1 PR
```

例如：

```text
P2.5-A01
P2.5-A02
P2.5-B02
P2.5-C01
```

不得将：

```text
Query Understanding
+
FTS5
+
Concurrency
+
Ranking
```

一次性揉进一个 PR。

---

# 4. Scope Contract

每个 Task 必须声明：

```text
Allowed Files
Forbidden Files
Required Tests
Required Benchmark
Acceptance Criteria
```

Agent 不得超出 Scope。

例外只能是：

- 公共 API 必须同步
- 测试 fixture 必须新增
- Contract 文档必须同步
- Release Gate 必须同步

额外修改必须写入最终报告。

---

# 5. Architecture Redlines

Agent 永远不得破坏：

```text
Search != Action Authority
```

Search 禁止直接调用：

```text
launcher-action::execute()
```

Search 禁止：

- filesystem mutation
- plugin installation
- capability approval
- trust mutation
- authorization
- Effect execution

---

# 6. Determinism

同一：

```text
query
data
context
user state
ranking weights
```

必须得到相同：

```text
candidate set
identity
score
order
explanation
```

禁止将以下内容作为排序依据：

- task completion order
- random UUID
- wall-clock time
- OS scheduling
- thread order

---

# 7. Concurrency

所有并发必须 bounded。

允许：

```text
Semaphore
bounded channel
fixed worker pool
```

禁止：

```text
unbounded queue
unbounded spawn
unbounded buffer
```

每个 Coordinator PR 都必须测试：

```text
max_in_flight
task cleanup
cancellation
timeout
```

---

# 8. Timeout

Provider 必须具备 bounded timeout。

Global 必须存在：

```text
soft deadline
hard deadline
```

要求：

```text
Provider A timeout
≠
Provider B cancelled
```

---

# 9. Cancellation

至少处理：

```text
explicit cancel
supersede
global deadline
provider deadline
```

不得留下 orphan tasks。

---

# 10. Query Parser

必须：

- deterministic
- pure
- bounded
- Unicode-safe

禁止：

- LLM
- network
- filesystem
- current time

---

# 11. FTS5

FTS5 仅属于 retrieval：

```text
FTS5
→ Candidate
→ Identity
→ Ranking
```

不得：

```text
FTS5 score
→ direct UI rank
```

必须保留：

```text
LIKE fallback
```

不得为了 FTS5：

- 删除旧 metadata path
- 改变 IndexGeneration
- 重写整个 Indexer
- 阻塞 launcher startup
- 默认启动全文内容扫描

---

# 12. Pinyin

Pinyin 是：

```text
retrieval signal
ranking signal
```

不是：

```text
identity
authority
capability
```

---

# 13. Explainability

必须复用真实 ranking contribution：

```rust
ScoreParts
    ↓
total
    ↓
explanation
```

禁止：

```text
Ranking Algorithm A
Explanation Algorithm B
```

---

# 14. Generation

新增 Generation 前：

1. 修改横向契约。
2. 定义 owner。
3. 定义递增条件。
4. 定义 persistence。
5. 定义 cache impact。
6. 定义 restart behavior。

不允许自行创造：

```text
generation_count
version_counter
timestamp_as_generation
```

---

# 15. Test First

性能或并发 Task：

```text
test
→ implementation
→ benchmark
```

必须产生：

```text
regression test
unit/integration test
benchmark
```

---

# 16. Agent Stop Conditions

遇到以下情况立即：

```text
BLOCKED
```

而不是自行扩 scope：

1. Frozen Contract 冲突。
2. 需要改变 Action Authority。
3. 需要修改 Identity semantics。
4. 需要改变既有 Generation semantics。
5. 需要 LLM 才能实现当前任务。
6. 需要无界 concurrency。
7. FTS migration 可能丢数据。
8. fallback 无法保留。
9. 性能超过 hard budget 且无法局部解决。
10. 实际需求已经属于 P2.6/P2.7。

---

# 18. Reviewer Checklist

- [ ] Search / Action authority 未改变
- [ ] Identity 未改变
- [ ] Candidate merge 不丢 metadata
- [ ] deterministic
- [ ] bounded concurrency
- [ ] timeout isolation
- [ ] cancellation 正确
- [ ] partial result 语义正确
- [ ] FTS fallback 存在
- [ ] ranking invariant 保持
- [ ] explanation 与 score 一致
- [ ] test 覆盖
- [ ] benchmark 覆盖
- [ ] 无 scope creep
