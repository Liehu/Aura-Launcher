## 这轮实现有几个重要结果

### 1. F6 现在是真正的 identity 边界

从：

```text
selection-changed(int)
```

变成：

```text
selection-changed(command_id)
```

这一点比“index 在 Rust 里最终还原成 id”更干净。

现在可以把它理解为：

```text id="xz0m6a"
Slint
  ↓ command_id
UI Controller
  ↓ command_id
Core
```

而不是：

```text id="z5hsy4"
Slint
  ↓ index
Rust
  ↓ lookup
command_id
```

所以 UI-CONTRACT §17 的：

> 禁止 index 作 identity

现在确实已经覆盖到了**跨边界事件通道**，不只是执行 API。

---

### 2. Main.Error 的语义已经闭合

现在状态可以明确区分：

```text id="r8y6s2"
⌛ Searching
      ↓
┌───────────────┬─────────────────┐
↓               ↓
Results       Empty
                │
        ┌───────┴────────┐
        ↓                ↓
     no error         error
        ↓                ↓
   No results      Search failed
```

这解决了之前最明显的 UX 误导：

```text id="0n9e1l"

    ↓
No results
```

这种情况现在不会再被用户理解成“确实没有结果”。

---

### 3. Workflow Surface 的设计没有越界

这点也符合原契约。

当前：

```text id="qz97p3"

   ↓

   ↓
Slint
```

而不是：

```text id="r67a2d"
Slint
   ↓
WorkflowRunner
```

UI 依然只是 Runtime Surface。

特别是：

```text id="8y5o0a"
Enter = Confirm
Esc   = Keep paused
```

而不是：

```text id="k0zhec"
Esc = cancel workflow
```

这个语义需要保持到最终实现。
