## Main Mode 拆分建议

下一轮不要做“视觉重设计”，只做**结构迁移 + Token 化 + Primitive 复用**。

建议目标结构：

```text
launcher-ui/
└── ui/
    ├── app.slint
    ├── launcher-window.slint
    ├── search-box.slint
    ├── result-list.slint
    ├── result-row.slint
    ├── context-hint.slint
    ├── status-line.slint
    ├── primitives/
    │   ├── selected-marker.slint
    │   ├── state-symbol.slint
    │   ├── shortcut-badge.slint
    │   ├── focus-ring.slint
    │   └── divider.slint
    └── theme.slint
```

### 拆分边界

```text
LauncherWindow
    ├── SearchBox
    ├── ResultList
    │    └── ResultRow*
    ├── ContextHint
    └── StatusLine
```

其中：

**`SearchBox`**

只负责：

```text
text
placeholder
focus
search affordance
```

不负责提交查询。

**`ResultList`**

负责：

```text
visible rows
selection presentation
empty / searching / error presentation
```

不负责决定哪个 Command 可以执行。

**`ResultRow`**

输入建议只围绕 Presentation：

```text
title
subtitle
icon/presentation
selected
enabled
shortcut
```

并使用：

```text
SelectedMarker
ShortcutBadge
FocusRing
```

不重新实现这些视觉逻辑。

**`ContextHint`**

严格保持目前的边界：

```text
Core-provided presentation
        ↓
ContextHint
```

不能让组件自己访问 Explorer。

**`StatusLine`**

只负责呈现：

```text
Searching
Ready
No results
Search failed
```

不要让它根据字符串自己判断状态类型。

## Main 这一轮最值得守住的 5 个边界

### 1. 不要把 `app.slint` 清空后重写

应该：

```text
现有 app.slint
    ↓
逐块抽组件
    ↓
保持 callback / binding 行为
```

而不是：

```text
旧 app.slint
    ↓
新 app.slint
```

这样最能保证 Fully Conformant 行为不回退。

### 2. Selection 继续使用 `command_id`

尤其不要在组件拆分过程中重新出现：

```text
selected-index
```

目前这条边界已经彻底打通，没必要回退。

### 3. `ResultRow` 不知道什么叫 Primary Action

Main 只呈现 Command。

```text
CommandPresentation
    ↓
ResultRow
```

Primary 属于 Action 层。

### 4. Search Error 与 Empty 继续保持不同 Presentation

```text
Empty:
No results

Error:
⚠ Search failed: ...
```

不要为了复用组件而重新合并。

### 5. Context Hint 不应成为新的一层 UI

继续保持：

```text
Main
├── Search
├── Results
└── Context / Status
```

不要因为拆成独立 `ContextHint` 就把它变成一个大型 Card。
