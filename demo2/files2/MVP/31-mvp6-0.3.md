## F1 的修复尤其重要

原来的漏洞是：

```text
Command A
  ↓
ConfirmationPending(A)
  ↓
用户切换到 Command B
  ↓
pending_confirmation 仍然是 A
```

这会导致：

```text
B → A
↓
Enter
↓
直接确认 A
```

本质上是一个**状态身份失配**问题。

现在：

```text
selection_changed
    ↓
clear pending_confirmation
```

之后就变成：

```text
A
 ↓
ConfirmationPending(A)
 ↓
切换 B
 ↓
Cancel Pending
 ↓
切换 A
 ↓
Normal
 ↓
Enter
 ↓
重新 arm confirmation
```

这比简单修 UI 文案重要得多，因为它是在保护 **Confirmation state 与 selected identity 的绑定关系**。

# 当前 6 个遗留项，我建议不要按审计表的顺序机械推进

我会稍微调整优先级。

## 第一批：F2 + F6

这两个确实应该最先做。

### F2：`selected` 非颜色表达

当前：

```text
CommandPresentation.selected
```

还没有真正形成 UI 可消费的状态字段。

建议直接让：

```rust
CommandPresentation {
    ...
    selected: bool,
}
```

成为正式 Presentation 属性。

然后 UI：

```text
selected
  ├── visual highlight
  ├── focus semantics
  └── accessibility state
```

这样就不用把“选中”依赖在颜色上。

### F6：selection signal 的 index

这里要区分两件事：

```text
UI event transport
        ≠
business identity
```

如果：

```text
index
```

只是 Slint 内部 signal 用来通知 Rust 当前视觉选择变化，而真正执行继续使用：

```text
command_id
```

那么它不是架构违规。

但现在既然已经开始清理 Contract，最好让 Selection Model 最终直接走：

```text
selected_command_id
```

至少在 Presentation/Controller 边界不要再暴露“index 是业务选择”的感觉。

# 第二批：P0-UI-003 / 004

这里实际上是在补**Main Mode 的状态完整性**。

当前：

```text
Main.Results ✅
Main.Empty ✅
Main.Searching ❌
Main.Error ❌
```

尤其是：

> Provider 失败被静默成空结果

这个 UX 语义不太好。

因为：

```text
No Results
```

和：

```text
Search Failed
```

是两个完全不同的状态。

建议至少形成：

```text
Searching
  ↓
Results

Searching
  ↓
Empty

Searching
  ↓
Error
```

不要：

```text
Searching
  ↓
Provider failed
  ↓
Empty
```

否则用户会错误地理解为“确实没有结果”。

# F4 Context Hint

这一项可以紧随其后。

这里不需要做复杂 Context 面板。

保持你之前冻结的原则：

```text
Context = invisible input
```

只增加：

```text
ContextHint
```

例如：

```text
📁 Documents
```

或：

```text
Explorer · Documents
```

就足够。

重点是：

```text
ContextSnapshot
     ↓
Core
     ↓
ContextPresentation
     ↓
UI
```

而不是：

```text
UI → 自己读取 Explorer
```

这样不会破坏 Context 所有权。

# 目前我不会修改 UI Contract 本身

这一点很重要。

现在审计发现的是：

```text
Implementation gap
```

而不是：

```text
Contract flaw
```

所以不要为了适配现有实现去降低 Contract。

特别是：

```text
UI-CONTRACT
    ↓
必须实现
```

而不是：

```text

    ↓
反推契约
```

你这一轮审计实际上已经证明：

> 当前 Contract 足够具体，能够反向发现真实代码缺口。

这正是 Contract-driven UI 的价值。
