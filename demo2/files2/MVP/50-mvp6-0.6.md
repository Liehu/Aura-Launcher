可以，而且这正是 Windows 原生 Launcher 比较典型的实现方式。

你现在的现象：

```text
Ctrl+Space
   ↓
显示 Launcher Window
   ↓
Windows 将这个可见窗口作为普通应用窗口
   ↓
任务栏出现图标
```

而你希望的是：

```text
程序常驻
   │
   ├── 托盘/状态栏图标  ← 显示
   │
   └── Launcher Window  ← 显示时也不进入任务栏
```

Windows 官方支持这种行为。核心不是隐藏进程，而是**让 Launcher 窗口成为 Tool Window，而不是 App Window**。Windows Shell 对 `WS_EX_TOOLWINDOW` 窗口不会创建任务栏按钮；`Shell_NotifyIcon` 则负责把图标放进任务栏的通知区域/状态区域。([Microsoft Learn][1])

# 你的项目应该这样设计

## 1. 常驻托盘图标

程序启动后：

```text
launcher.exe
   │
   ├── Hidden Resident Window
   │
   ├── Tray Icon
   │
   └── Launcher Popup Window
```

Tray Icon 使用：

```text
Shell_NotifyIconW
```

主要操作：

```text
NIM_ADD
NIM_MODIFY
NIM_DELETE
```

Windows 文档明确说明 `Shell_NotifyIcon` 用于向任务栏的状态区域添加/修改/删除图标。([Microsoft Learn][2])

所以你的托盘生命周期应该是：

```text
Application Start
    ↓
Create Tray Icon
    ↓
Create Launcher Window
    ↓
Hide

Ctrl+Space
    ↓
Show Launcher
    ↓
Focus SearchBox

Esc / Enter / Lost focus
    ↓
Hide Launcher

Application Exit
    ↓
Remove Tray Icon
```

# 2. Launcher Window 不进入任务栏

关键是这个窗口的 Windows extended style：

```text
WS_EX_TOOLWINDOW
```

而不是：

```text
WS_EX_APPWINDOW
```

Windows 官方对此的定义非常直接：

```text
WS_EX_APPWINDOW
    → 显示任务栏按钮

WS_EX_TOOLWINDOW
    → 不显示任务栏按钮
```

([Microsoft Learn][1])

所以最终应该：

```text
Launcher Window

WS_POPUP
WS_EX_TOOLWINDOW
```

而不是：

```text
WS_OVERLAPPEDWINDOW
WS_EX_APPWINDOW
```

---

# 3. 还有一个容易踩坑的地方：Owner

Windows 还有另一种方式：

```text
Hidden Owner Window
        ↓
Launcher Window
```

如果可见 Launcher Window 有一个隐藏 owner，Shell 也可以不为它创建独立任务栏按钮。微软文档也明确提到了这种方式。([Microsoft Learn][1])

但是对于你的 Launcher，我更建议：

```text
WS_EX_TOOLWINDOW
```

作为第一方案。

原因是你的窗口本质就是：

> transient launcher popup

而不是传统意义上的应用主窗口。

---

# 4. 不要靠 AppUserModelID 解决

这里有一个很容易走错的方向。

`AppUserModelID` 主要解决的是：

```text
任务栏身份
任务栏分组
Jump List
固定
重启命令
```

而不是：

```text
“这个窗口不要出现在任务栏”
```

微软文档说明 AppUserModelID 会影响窗口的 Shell identity/grouping。([Microsoft Learn][3])

所以你的设计应该是：

```text
Taskbar suppression
        ↓
WS_EX_TOOLWINDOW
```

而不是：

```text
AppUserModelID
        ↓
试图让窗口消失
```

# 6. 另外建议增加一个“隐藏状态”的正式模型

现在你的 Launcher 实际上不是：

```text
Running / Closed
```

而是：

```text
Resident
   │
   ├── Hidden
   │
   └── Visible
```

建议冻结成：

```text
LauncherWindowState

Hidden
Visible(Main)
Visible(Action)
```

而：

```text
TrayState
    Present
    Removing
    Removed
```

这样 Ctrl+Space 的行为就是：

```text
Hidden
   │
   │ Ctrl+Space
   ▼
Visible(Main)
   │
   │ Esc / execute / dismiss
   ▼
Hidden
```

**进程永远不需要退出。**

这与你现在的：

> hidden resident popup + transient workspace

设计是完全一致的。

# 7. 你还需要处理“任务栏图标”和“状态栏图标”是两个东西

Windows UI 术语上最好区分：

```text
Taskbar
┌──────────────────────────────────────────────┐
│ ...                              Launcher  ❌ │
└──────────────────────────────────────────────┘

Notification Area / System Tray
┌─────────────────────────────────────┐
│ ^  Network  Volume  Battery  🚀    │
│                           Launcher ✅│
└─────────────────────────────────────┘
```

目标不是：

```text
“不显示图标”
```

而是：

```text
Taskbar Button       = Disabled
Notification Icon    = Enabled
```

这正是 `WS_EX_TOOLWINDOW + Shell_NotifyIcon` 的组合。

# 8. 对你的 MVP，建议直接把验收标准写进去

可以增加一个 UI/Windows platform gate：

### WIN-TRAY-001

```text
Launcher process resident
    AND
Launcher window hidden
    AND
Tray icon exists
    AND
Taskbar button absent
```

### WIN-TRAY-002

```text
Ctrl+Space
→ Launcher visible
→ Taskbar button remains absent
→ Tray icon remains present
```

### WIN-TRAY-003

```text
Esc
→ Launcher hidden
→ process remains resident
→ tray icon remains present
```

### WIN-TRAY-004

```text
Exit
→ launcher window destroyed
→ tray icon removed
→ process terminated
```

### WIN-TRAY-005

```text
Action mode / Workflow mode
→ taskbar button remains absent
```

### WIN-TRAY-006

```text
Restart Explorer.exe
→ tray icon is re-registered
```

最后这一条值得做。Explorer 重启之后通知区域图标可能需要重新注册，所以托盘实现最好考虑 Explorer restart 的重新注册机制。

# 9. 对你目前项目，我建议的最终窗口拓扑

```text
launcher.exe
│
├── Resident / Message Window
│      └── Win32 message handling
│
├── Tray Icon
│      └── Shell_NotifyIconW
│
└── Launcher Popup
       │
       ├── WS_POPUP
       ├── WS_EX_TOOLWINDOW
       ├── no taskbar button
       │
       └── Slint
            │
            ├── Search
            ├── Results
            ├── Action
            └── Workflow
```

其中：

```text
Ctrl+Space
     ↓
show popup
     ↓
focus search
```

而**不是创建/销毁窗口**。

这样才最符合你前面冻结的“常驻、低内存、按需显示、Progressive Disclosure”设计。

另外，**不要为了去掉任务栏图标而把整个主窗口改成 `WS_EX_NOACTIVATE`**。Launcher 打开后仍然需要正常获取焦点、键盘输入和 `Ctrl+Down / Enter / Esc` 等交互；`WS_EX_NOACTIVATE` 会破坏这类行为。

如果你现在是直接用 **Slint 的 `Window`** 创建这个 launcher，我下一步建议直接针对你当前代码确认 **Slint 获取 HWND 的方式，以及在哪里设置 `WS_EX_TOOLWINDOW` + 托盘消息循环**，这样可以给出可以直接交给 Agent 实现的 `WIN-TRAY v0.1` 修改规范。
