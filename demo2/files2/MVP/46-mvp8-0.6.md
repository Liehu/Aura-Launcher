# 1. 最重要的漏洞：Tool Substitution

这是目前整个 MVP4.3 最有价值的一次安全发现。

问题本质：

```text
Proposal / Reference
    ↓
resolve(evaluate)
    ↓
resolved identity = evaluate

step.input
    ↓
tool_name = delete_all
```

如果没有额外校验，就变成：

```text id="tool-substitution"
Authorized:
    mcp:calc / evaluate

Executed:
    mcp:calc / delete_all
```

这正是典型的 **confused deputy / identity substitution**。

你现在把：

```rust
identity_mismatch(...)
```

放在 Runner 的 Reference binding point，是正确的。

因为那里第一次同时拥有：

```text
ActionReference identity
+
Step.input execution identity
```

并且你没有写：

```rust
if mcp { ... }
```

而是抽象成：

```text
frozen identity fields
    server_id
    tool_name
```

因此这不是 MCP workaround，而是一个**通用 Workflow integrity rule**。

建议正式冻结为：

> **A resolved action may execute only when authoritative execution-input identity is consistent with the identity bound during reference resolution.**

# 2. A-002 改成 ProtocolViolation 是正确的

这里从：

```text
InvalidInput
```

升级为：

```text
ProtocolViolation
```

语义更准确。

例如：

```text
provider_id = mcp:calc
input.server_id = jira
```

这不是普通用户参数错误，而是：

> 已构造出的内部执行对象违反了跨层协议 invariant。

因此：

```text
ProtocolViolation
    ↓
Stop
    ↓
Never Retry
```

比 `InvalidInput → 可能 Skip/其它 policy` 更符合安全边界。

# 3. E-003 修复非常关键

你发现：

```text
tools/call
```

收到：

```text
tools/list envelope
```

原实现可以被 serde “成功”解析成：

```text
empty result
```

这是典型的 **structural validation bypass**：

```text
JSON valid
    ≠
Protocol semantically valid
```

现在要求：

```text
tools/call response
    must contain at least one valid result discriminator:
        content
        isError
        structuredContent
```

否则：

```text
ProtocolViolation
```

正确。

这一原则以后也应该扩展到：

```text
initialize
tools/list
tools/call
```

即：

> **每个 MCP RPC method 都必须验证 method-specific envelope semantics，而不能只依赖 serde structural deserialization。**

# 4. 256 KB reader hardening 是实质性的 DoS 修复

之前危险模式：

```text
read whole frame
    ↓
then check size
```

攻击者可以：

```text
huge stdout
    ↓
memory allocation
    ↓
OOM
```

现在：

```text
bounded take()
    ↓
256 KB limit
    ↓
reject
```

才是真正的：

```text
bounded input
```

这比单纯：

```rust
if buffer.len() > MAX
```

强得多。

因为安全边界应该放在：

```text
allocation boundary
```

而不只是：

```text
semantic validation boundary
```

这是 Phase 10 应保留的实现级安全原则。

# 5. Crash / Truncation 从 Timeout 中分离也是正确的

现在：

```text
server crash
    → ProcessCrashed

server exits without complete response
    → ServerUnavailable / ProcessCrashed

actual wait exceeded deadline
    → Timeout
```

这非常重要，因为 Workflow 的 retry semantics 不应该被错误分类污染。

例如：

```text
Timeout
    → Retry

ProtocolViolation
    → Stop

ProcessCrashed
    → bounded retry / stop
```

因此：

> **FailureClass 不是 UI message，它实际上决定了系统行为。**

你现在的单点 `failure_class()` 设计已经体现了这一点。

# 6. A-001 结构级身份约束值得正式提升为 Contract

现在：

```text
server_id
tool_name
```

拒绝：

```text
/
\
:
..
leading/trailing whitespace
non-printable
```

并限制：

```text
arguments <= 256 KB
```

这很好，但需要明确一个概念：

这些约束不是为了“防止 Windows 路径穿越”这么狭窄。

更准确是：

> **Launcher canonical identity fields 必须具有受控、无歧义的 lexical representation。**

否则以后可能出现：

```text
calc
calc/
calc\ 
calc..
```

在不同 subsystem 中拥有不同解释。

所以建议正式写：

```text
Canonical Identity Fields
    server_id
    tool_name
```

而不是仅称为 `input validation`。

# 13. 我建议 Phase 10 最后再冻结 6 条全局 Security Invariants

现在这些规则实际上已经成熟到可以脱离 MCP。

### INV-AUTH-001

```text
Non-executable resolution MUST NOT reach an Effect Executor.
```

### INV-AUTH-002

```text
External metadata MUST NOT increase execution authority.
```

### INV-AUTH-003

```text
Execution identity MUST remain consistent from Reference
resolution through Effect execution.
```

### INV-AUTH-004

```text
Confirmation MUST NOT authorize a stale or replaced Action.
```

### INV-AUTH-005

```text
Each execution attempt MUST have exactly one execution_id.
```

### INV-AUTH-006

```text
Protocol/transport failures MUST NOT be silently converted into
successful business results.
```

其中第 3 条就是这次 `Tool substitution` 漏洞的抽象结果。
