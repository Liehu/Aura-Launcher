覆盖：

```text

        ↓
Cross-Phase Audit
        ↓

        ↓

        ↓

        ↓

        ↓
P3 Architecture Baseline
```

---

# 2. 为什么必须设置 P2.10

P2.6–P2.9 已经分别建立：

```text
Workflow
AI / Agent
Plugin Ecosystem
System Integration
```

但这些模块开始真正组合后，新的风险不再主要来自单个模块，而来自：

```text
A 模块的合法状态
        +
B 模块的合法状态
        +
C 模块的合法状态
        =
跨模块非法组合
```

因此 P2.10 不再以：

```text
功能数量
测试数量
代码行数
```

作为核心指标，而以：

```text
Invariant
Authority
State
Effect
Recovery
Cross-Phase E2E
```

作为核心指标。

# 5. H1 — Effect Authority Hardening

## 5.1 当前基础

项目已有明确原则：

```text
ActionEngine = 唯一 Effect 闸门
```

并且 Handbook 已明确：

```text
一切执行经 Resolver → Engine
```

P2.10 不推翻它，而是把“入口唯一”进一步升级为：

> **类型层面不可绕过。**

---

# 6. Authorized Effect

推荐增加明确的授权后对象：

```text
ValidatedCommand
        ↓
PolicyDecision
        ↓
ApprovalDecision
        ↓
AuthorizedEffect
```

定义：

```text
Command
≠
ResolvedCommand
≠
AuthorizedEffect
≠
OS Effect
```

其中：

```text
AuthorizedEffect
```

只能由：

```text
ActionEngine
```

生成。

---

# 7. 禁止 confirmed 布尔值成为 Authority

当前 P2.9 Windows Adapter：

```text
execute_system_command(
    &SystemCommand,
    confirmed
)
```

其中：

```text
confirmed=true
```

不应继续作为底层 Effect 授权凭证。

P2.10 应逐步收敛为：

```text
SystemCommand
       ↓
ActionEngine
       ↓
AuthorizedSystemEffect
       ↓
WindowsSystemAdapter
```

Adapter 不再接收：

```text
confirmed: bool
```

# 9. H2 — Dynamic Target Hardening

P2.9 的真实 OS Effect 带来了动态目标问题：

```text
Resolve
   ↓
time passes
   ↓
target changes
   ↓
execute
```

P2.10 要求所有动态资源建立统一：

```text
TargetIdentity
```

---

# 10. Process Identity

禁止：

```text
PID only
```

必须至少：

```text
ProcessTarget {
    pid
    identity
}
```

其中 identity 用于确认：

```text
当前 PID
=
原 Resolve 时的同一个进程
```

如果：

```text
PID same
identity different
```

结果：

```text
StaleTarget
```

绝不能执行。

---

# 11. HWND Identity

禁止：

```text
WindowTitle only
```

统一为：

```text
WindowTarget {
    hwnd
    process_identity
    window_identity
}
```

执行前：

```text
Validate HWND
+
Validate Process
+
Validate Window identity
```

---

# 12. File Identity

对于高风险 File Effect：

```text
canonical path
+
identity metadata when available
```

至少防止：

```text
resolve file A
↓
file A deleted
↓
file B appears at same path
↓
delete B
```

若目标身份变化：

```text
StaleTarget
```

# 13. H3 — Replan Safety

当前 P2.7 Agent Loop 文档明确记录：

```text
步骤失败
→ Replanning
→ Planning
→ Executing
→ 全 plan 从头重执行一次
```

P2.10 必须将该语义废止。

---

# 14. Replan 不得重新执行成功 Effect

建立：

```text
StepExecutionRecord
```

至少记录：

```text
step_id
execution_id
attempt
status
effect_state
started_at
finished_at
```

---

# 15. Step Result

统一：

```text
Pending
Executing
Succeeded
Failed
Cancelled
Unknown
Skipped
```

Agent Replan 必须：

```text
Succeeded
    → immutable success
    → 不重复执行
```

---

# 16. Replacement Suffix

原计划：

```text
A → B → C → D
```

执行：

```text
A ✓
B ✓
C ✕
```

新计划：

```text
A ✓
B ✓
C'
D'
```

而不是：

```text
A
B
C'
D'
```

重新执行。

---

# 17. Effect State

对于真实 Effect：

```text
NotStarted
Started
Completed
Failed
Unknown
```

尤其：

```text
Timeout
```

不允许自动变成：

```text
Failed
```

# 18. H4 — Timeout / Unknown 统一语义

新建：

```text
docs/contracts/EXECUTION-SEMANTICS-v1.md
```

统一规定：

```text
CommandResult:
    Succeeded
    Failed
    Rejected
    Cancelled
    Timeout
    Unknown
```

以及：

```text
EffectState:
    NotStarted
    Started
    Completed
    Failed
    Unknown
```

---

# 19. Timeout Rule

如果：

```text
Effect started
+
caller timeout
```

默认：

```text
Result = Timeout
EffectState = Unknown
```

而不是：

```text
Result = Failed
EffectState = NotStarted
```

---

# 20. Retry Rule

Retry 必须检查：

```text
idempotency
+
effect_state
+
target_identity
+
transaction_state
```

规则：

```text
Unknown + NonIdempotent
    → no automatic retry

Unknown + Idempotent
    → policy-controlled retry

Completed
    → no duplicate retry
```

每一次 Retry：

```text
new ExecutionId
```

# 21. H5 — Cross-Phase State Model

当前各阶段已经有多个状态体系：

```text
Workflow Run
Workflow Step
Agent Session
Agent Run
Plugin Installation
Plugin Runtime
System Command
Approval
```

P2.10 不要求所有状态变成一套 enum。

而要求：

> **定义统一的状态语义层。**

---

# 22. Lifecycle State 分类

统一分成：

```text
Intent State
Planning State
Authorization State
Execution State
Resource State
Recovery State
```

例如：

```text
Agent:
    Planning

Workflow:
    Running

Approval:
    Pending

System Effect:
    Executing

Plugin:
    Running
```

这些状态不能互相替代。

---

# 23. State 不得承担 Authority

例如：

```text
status = Approved
```

不能意味着：

```text
Capability granted
```

或者：

```text
status = Running
```

不能意味着：

```text
Effect authorized
```

---

# 24. Generation Registry

统一维护：

```text
docs/contracts/GENERATION-REGISTRY.md
```

每个 generation 必须回答：

```text
What does it version?
When does it increment?
What invalidates it?
Can failure increment it?
```

基本规则继续保持：

```text
Committed state changed
    → generation +1
```

失败：

```text
generation unchanged
```

---

# 25. Generation 不得替代 Identity

禁止：

```text
generation = identity
```

例如：

```text
WindowGeneration
```

只能表示：

```text
窗口上下文版本
```

不能代替：

```text
HWND / WindowIdentity
```
