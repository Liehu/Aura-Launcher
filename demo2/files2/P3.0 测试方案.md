# 1. 测试策略

测试数量不再是完成度证据（103 号评审 §12）。本方案按**维度矩阵**组织：
每个特性必须覆盖「属性 → 边界 → 集成 → 体验回归」四层；性能预算是
硬验收项。载体沿用既有体系：crate 单测 + integration 测试 + VR 基线 +
keyboard walkthrough。

# 2. F01 模糊子序列匹配

## 属性测试（proptest 风格，确定性断言）

| # | 属性 |
|---|---|
| FUZ-P1 | 确定性：同 (candidate, query) 恒同分 |
| FUZ-P2 | 子序列不成立 → None（穷举反例语料） |
| FUZ-P3 | 前缀命中 ≥ 词边界命中 ≥ 分散命中（严格序） |
| FUZ-P4 | 连续段越长分越高；gap 越大分越低 |
| FUZ-P5 | 空 query / 空 candidate → None |
| FUZ-P6 | 大小写折叠：`CHR` ≡ `chr` |
| FUZ-P7 | CJK 与拼音串参与匹配（`wj` → 文件夹，`wenjian` 同） |
| FUZ-P8 | 分数有界（不超过设计上限 40 分贡献） |

## 边界语料（冻结）

```text
"chrome" vs "chr" / "cme"（首尾子序列）/ "xyz"（None）
"文件夹" vs "wj" / "wenjianjia"（拼音双键）
"report 2026.pdf" vs "r2p"（跨词跳转）
query 长度 > candidate / 全 Unicode / 全空白
```

## 集成

| # | 内容 |
|---|---|
| FUZ-I1 | rank_with_boost 合并：模糊命中与 FTS 命中去重后统一排序 |
| FUZ-I2 | 模糊分量不改变非模糊结果的既有相对序（回归） |
| FUZ-I3 | 性能预算：10k 候选 P95 < 5ms（基准测试，数字入批次文档） |
