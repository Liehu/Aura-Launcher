# P2.2-C — Context-aware Ranking v0.1

这一批正式把：

```text
Context Snapshot
        ↓
Context Signals
        ↓
deterministic ranking
        ↓
ContextGeneration
        ↓
SearchCache invalidation
```

冻结下来。

核心目标不是做“AI 猜测用户意图”，而是先建立一个**可解释、可测试、可关闭、不会污染权限边界**的 Context Ranking 第一版。

---

# 1. P2.2-C 批次边界

## 本批次做

```text
Context Snapshot
Context Provider
Context Signals
Context Generation
Deterministic Context Ranking
SearchCoordinator integration
Query Cache invalidation
Context settings
Context diagnostics
```

## 本批次不做

```text
❌ ML ranking
❌ Embedding
❌ AI inference
❌ Window title NLP
❌ Clipboard content analysis
❌ Document content analysis
❌ User behavior prediction model
❌ Cross-device context sync
❌ Cloud context
❌ Workflow context
❌ Agent context
```

核心原则：

> **Context 只能影响“排序”，不能影响“权限、Action Resolver 或 Effect”。**

---

# 2. Context 的定义

Context 不是一个大的“当前用户状态对象”。

它应该是：

> 在一次 Search Request 开始时，对与当前搜索相关的少量环境信息进行一次确定性采样。

即：

```text
User Environment
       │
       ▼
Context Snapshot
       │
       ▼
Context Signals
       │
       ▼
Ranking Features
```

---

# 3. Context Snapshot

建议：

```rust
pub struct ContextSnapshot {
    pub captured_at: Instant,
    pub generation: ContextGeneration,

    pub foreground_application:
        Option<ApplicationIdentityV2>,

    pub current_folder:
        Option<FileIdentity>,

    pub invocation_source:
        InvocationSource,

    pub time_bucket:
        TimeBucket,
}
```

注意：

> Snapshot 是一次 Search Request 的输入，不是持续变化的全局 mutable object。

---

# 4. 为什么必须 Snapshot

假设用户在搜索期间：

```text
Folder A
```

然后窗口切换：

```text
Folder B
```

如果不同 Provider 在不同时间分别读取：

```text
Foreground
CurrentFolder
```

可能得到：

```text
Provider A → A
Provider B → B
```

最终结果不可重复。

正确：

```text
T0
   ↓
ContextSnapshot = Folder A
   ↓
所有 Provider / Ranking
   ↓
same snapshot
```

---

# 5. ContextGeneration

正式定义：

```rust
pub struct ContextGeneration(pub u64);
```

Context Generation 表示：

> 当前 Context Snapshot 所代表的 Context 状态版本。

---

# 6. Generation 更新条件

第一版只在**会影响 Ranking 的 Context 发生变化**时递增。

例如：

```text
foreground application changed
current folder changed
invocation source changed
time bucket changed
```

则：

```text
N → N+1
```

不应因为：

```text
mouse moved
window repainted
CPU changed
```

递增。

---

# 7. ContextGeneration 不等于时间戳

错误：

```rust
generation = timestamp
```

正确：

```text
Context changed
    ↓
generation += 1
```

这样可以：

```text
compare
cache
diagnostics
```

而无需依赖 wall-clock。

---

# 8. Foreground Application

第一版只记录：

```text
ApplicationIdentityV2
```

例如：

```text
VS Code
Chrome
Windows Terminal
Explorer
```

不保存：

```text
window title
document name
URL
clipboard
screen contents
```

这会让 Context Model 保持非常小。

# 9. Current Folder

如果 Launcher 是从文件管理器上下文触发，或者能可靠确定当前 Explorer folder：

```text
C:\Projects\Launcher
```

生成：

```rust
Some(FileIdentity::Folder(...))
```

否则：

```rust
None
```

不能猜测。

# 10. Invocation Source

建议：

```rust
pub enum InvocationSource {
    GlobalHotkey,
    Tray,
    ContextAction,
}
```

第一版真正使用：

```text
GlobalHotkey
Tray
```

`ContextAction` 只是预留。

---

# 11. TimeBucket

不要保存精确时间。

建议：

```rust
pub enum TimeBucket {
    Night,
    Morning,
    Afternoon,
    Evening,
}
```

时间桶只用于：

```text
deterministic weak signal
```

而不是行为监控。

---

# 12. 为什么不使用精确时间

否则：

```text
08:31
08:32
```

会导致：

```text
ContextGeneration
```

不断变化。

然后：

```text
SearchCache
```

不断失效。

所以 TimeBucket 必须离散化。

---

# 13. Context Provider

建议抽象：

```rust
pub trait ContextProvider {
    fn capture(&self) -> ContextSnapshot;
}
```

Windows implementation：

```text
WindowsContextProvider
```

负责：

```text
foreground application
current folder
time bucket
invocation source
```

---

# 14. ContextProvider 不进入 SearchProvider

这是一个重要边界。

不要：

```text
ContextProvider
    implements SearchProvider
```

Context 不产生 SearchCandidate。

它产生：

```text
ContextSnapshot
```

然后：

```text
SearchCoordinator
    + ContextSnapshot
```

---

# 15. Context Snapshot 生命周期

正确：

```text
Search Request
    ↓
capture context once
    ↓
SearchSnapshot
```

不要：

```text
Provider A → capture
Provider B → capture
Provider C → capture
```

---

# 16. SearchCoordinator 集成

最终：

```text
User Query
    │
    ▼
SearchCoordinator
    │
    ├── normalize query
    ├── capture ContextSnapshot
    ├── build CacheKey
    │
    ▼
Cache Lookup
```

因此 Cache Lookup 本身已经知道：

```text
context_generation
```

# 17. Cache Key

延续 P2.2-B：

```rust
pub struct SearchCacheKey {
    pub query: NormalizedQuery,
    pub mode: SearchMode,

    pub file_generation: IndexGeneration,
    pub application_generation:
        ApplicationCatalogGeneration,

    pub user_state_generation:
        UserStateGeneration,

    pub context_generation:
        ContextGeneration,

    pub ranking_generation:
        RankingGeneration,
}
```

P2.2-C 不修改这个结构。

只让：

```text
ContextGeneration
```

真正开始变化。

---

# 18. Context Change → Cache Invalidation

例如：

```text
ContextGeneration = 42
```

缓存：

```text
query = "git"
context = 42
```

用户切换：

```text
VS Code → Explorer
```

变成：

```text
ContextGeneration = 43
```

则：

```text
old cache key ≠ current key
```

自然：

```text
MISS
```

不需要：

```text
clear_all()
```

---

# 19. 不做全局 Cache Flush

禁止：

```text
foreground app changed
    ↓
SearchCache.clear()
```

这会把：

```text
all queries
```

全部浪费掉。

正确是：

```text
generation changed
    ↓
current key changes
    ↓
old entries naturally unreachable
```

之后再由 LRU 淘汰。

---

# 20. Context Signals

ContextSnapshot 不直接进入 Ranking。

先转换成：

```rust
pub struct ContextSignals {
    pub foreground_match: bool,
    pub folder_proximity: FolderProximity,
    pub time_bucket_match: bool,
    pub invocation_match: bool,
}
```

这样 Ranking 不依赖 Windows API。

---

# 21. FolderProximity

不要一开始做复杂路径距离。

推荐：

```rust
pub enum FolderProximity {
    None,
    SameFolder,
    Descendant,
    Ancestor,
}
```

例如：

```text
Current:
C:\Projects\Launcher

Candidate:
C:\Projects\Launcher\README.md
```

得到：

```text
Descendant
```

而：

```text
C:\Projects\Other
```

得到：

```text
None
```

---

# 22. Application Context Signal

对于 Application Candidate：

```text
Candidate.identity = Chrome
Foreground = Chrome
```

可以得到：

```text
foreground_match = true
```

对于 File Candidate：

```text
foreground application = VS Code
```

可以作为间接 signal，但 P2.2-C v0.1 建议：

> 不做“VS Code → 某种文件类型”的推断。

只支持精确 identity matching。

---

# 23. 当前 Folder Signal

Folder context 是最直接的 Context Ranking：

```text
query = "readme"
current folder = D:\Projects\Launcher
```

那么：

```text
D:\Projects\Launcher\README.md
```

优先于：

```text
D:\Archive\README.md
```

---

# 24. Ancestor / Descendant 关系

建议排序：

```text
SameFolder
    >
Descendant
    >
Ancestor
    >
None
```

但它只是：

```text
context boost
```

不能强制覆盖文本 relevance。

# 25. Text Relevance 仍然是第一优先级

例如：

```text
query = "chrome"
```

Context：

```text
current folder contains:
ChromeBackup.txt
```

而：

```text
Application:
Google Chrome
```

仍然应该：

```text
Google Chrome
    >
ChromeBackup.txt
```

Context 不能取代 Query relevance。

# 27. 不建议给 Context 一个总 boost

错误：

```text
context_boost = +50
```

然后：

```text

```

```text

```

这样：

```text

```

才能明确解释排名。

# 28. Context Ranking 是附加分

```text
final_score =
    text_score
  + provider_score
  + history_score
  + favorite_score
  + context_score
```

P2.2-C 只新增：

```text

```

不改变：

```text
text_score
provider_score
history_score

```

的定义。

# 46. Debouncing

Foreground window 在用户快速 Alt+Tab 时可能：

```text
A
B
A
B
```

短时间大量切换。

不需要每个事件都：

```text
generation++
```

建议：

```text
context changes
    ↓
debounce/coalesce
    ↓
publish latest stable snapshot
```

但 debounce 只是性能优化。

正确性上：

```text
snapshot captured at request time
```

依旧有效。

---

# 47. Context Snapshot Capture Timing

建议：

```text
T0 user submits query
T1 capture context
T2 build cache key
T3 cache lookup
```

不要：

```text
cache lookup
    ↓
capture context
```

否则 Cache Key 里的 ContextGeneration 可能与真正 SearchRanking 使用的 snapshot 不一致。

---

# 48. Cache Hit 的 Context

Cache hit：

```text
key context_generation = 42
```

当前：

```text
context_generation = 42
```

可以使用。

即使实际 foreground 当前：

```text
B
```

只要：

```text
ContextGeneration
```

尚未发布为 43，就说明当前 Search context snapshot 仍被认为稳定。

# 49. Context Change Race

场景：

```text
T0 context = A, generation = 42
T1 cache hit
T2 foreground changes B
T3 generation = 43
T4 result about to publish
```

此时必须：

```text
discard stale result
```

否则：

```text
context 42 result
```

可能显示在：

```text
context 43
```


# 100. Security Invariants

Context generation changes only when semantic ranking-relevant context changes.

### `INV-CONTEXT-005`

Context capture failure degrades to missing fields, not Search failure.

### `INV-CONTEXT-006`

Context ranking is deterministic.

### `INV-CONTEXT-007`

Context does not create SearchCandidates.

### `INV-CONTEXT-008`

Context does not persist raw activity content.

Context changes invalidate cached ranked results through generation, not cache mutation.

Context cannot bypass SearchCoordinator or ActionResolver.
