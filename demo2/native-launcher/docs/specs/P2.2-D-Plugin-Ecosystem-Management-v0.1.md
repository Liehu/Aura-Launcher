# P2.2-D — Plugin Ecosystem Management v0.1

## 1. 批次目标

建立 Launcher 1.0 的插件生态管理能力。

本批次正式解决：

- Plugin Registry
- Plugin Package
- Manifest 验证
- Plugin identity
- Capability request / approval
- Install
- Enable / Disable
- Start / Stop
- Update
- Rollback
- Crash Quarantine
- Plugin diagnostics
- Plugin version lifecycle
- Plugin/Runtime/Host/Broker/ActionEngine 边界
- Plugin state persistence
- 安全失败与恢复

本批次不实现：

- Marketplace
- Cloud plugin repository
- Plugin automatic download discovery
- Plugin payment/licensing
- Plugin sandbox container
- Remote plugin execution
- WASM plugin runtime
- Plugin AI agent
- Plugin-created Workflow
- Plugin capability auto-grant
- Plugin self-update without host approval

# 2. 核心架构

最终插件系统：

```text
                    Plugin Package
                          │
                          ▼
                  Package Validator
                          │
                          ▼
                    Plugin Manifest
                          │
                          ▼
                   Plugin Registry
                          │
             ┌────────────┼────────────┐
             │            │            │
             ▼            ▼            ▼
          Policy       Lifecycle     Diagnostics
             │            │            │
             └────────────┼────────────┘
                          ▼
                    PluginBroker
                          │
                    RuntimeManager
                          │
                    ProcessSupervisor
                          │
                    Plugin Host Process
                          │
                    Plugin Protocol
                          │
                    Plugin Implementation
```

执行：

```text
ActionResolver
      ↓
launcher-action
      ↓
Effect
      ↓
PluginBroker
      ↓
Plugin Runtime
```

管理：

```text
Settings / Installer / Host
      ↓
Plugin Management Actions
      ↓
Plugin Registry / Service
```

两条路径必须保持分离。

# 3. Plugin Identity

正式冻结：

```rust
pub struct PluginId(pub String);
```

PluginId 必须：

- stable；
- case-normalized；
- 不受 display name 影响；
- 不包含 version；
- 不随安装目录变化。

例如：

```text
com.example.pdf-tools
```

身份：

```text
PluginId = com.example.pdf-tools
```

版本：

```text
1.2.0
```

不能成为 PluginId 的一部分。

---

# 4. Plugin Version

建议：

```rust
pub struct PluginVersion {
    pub major: u16,
    pub minor: u16,
    pub patch: u16,
}
```

v0.1 采用严格可排序版本。

不要把：

```text
"latest"
"stable"
"beta"
```

放进 runtime identity。

---

# 5. Installed Plugin Identity

最终：

```rust
pub struct InstalledPlugin {
    pub id: PluginId,
    pub version: PluginVersion,
    pub state: PluginState,
}
```

注意：

```text
PluginId
    ≠
InstalledInstanceId
```

推荐再保留：

```rust
pub struct PluginInstanceId(pub String);
```

用于：

- staging；
- update transaction；
- rollback；
- diagnostics。

这样：

```text
PluginId = stable logical identity
PluginInstanceId = installed physical revision
```

# 6. Plugin State

正式冻结：

```rust
pub enum PluginState {
    Discovered,
    Validating,
    Installed,
    Disabled,
    Enabled,
    Starting,
    Running,
    Stopping,
    Broken,
    Quarantined,
}
```

但这些状态不完全互斥于 lifecycle operation。

例如：

```text
Enabled + Running
Enabled + Broken
Disabled + Installed
```

因此更好的实现是拆成：

```rust
pub enum EnableState {
    Enabled,
    Disabled,
}

pub enum RuntimeState {
    Stopped,
    Starting,
    Running,
    Stopping,
    Crashed,
}
```

然后：

```rust
pub struct PluginStatus {
    pub enable_state: EnableState,
    pub runtime_state: RuntimeState,
    pub health: PluginHealth,
}
```

这样比一个超大 enum 更稳定。

---

# 7. Plugin Health

建议：

```rust
pub enum PluginHealth {
    Unknown,
    Healthy,
    Degraded,
    Broken,
    Quarantined,
}
```

例如：

```text
Enabled
Stopped
Healthy
```

是合法的。

这意味着：

> Enabled 表示用户允许插件运行，不代表插件当前进程一定在运行。

---

# 8. Disabled 与 Stopped 的区别

必须明确：

```text
Disabled
    = policy says plugin must not run

Stopped
    = plugin currently not running
```

因此：

```text
Enabled + Stopped
```

合法。

例如：

```text
persistent runtime = false
```

插件可能在：

```text
Enabled + Stopped
```

直到第一次执行时启动。

---

# 9. Quarantined

Quarantined 是：

> Host 侧强制阻止 Plugin Runtime 启动。

例如：

```text
Plugin
    enabled
    crash_count > threshold
```

进入：

```text
health = Quarantined
```

之后：

```text
PluginBroker
    → reject execution
```

直到：

```text
explicit host action
```

解除。

---

# 10. Quarantine 不等于 Disable

两者含义不同：

```text
Disabled
    = user choice

Quarantined
    = host safety state
```

因此 UI 必须能够同时显示：

```text
Enabled
Quarantined
```

这种状态。

# 11. Plugin Package

正式定义：

```text
PluginPackage
```

v0.1 建议：

```text
.plugin.zip
```

其内部：

```text

├── manifest.json
├── bin/
│   └── plugin.exe
├── resources/
└── signature/
```

但实际落盘格式可以是：

```text

```

扩展名只是 transport/package format。


```text

```

# 13. Plugin Package Layout Contract

最小：

```text

```


例如：

```text

```

不得因为包内存在就自动运行。

# 16. Manifest 不等于 Granted Capability

Manifest：

```json
"capabilities": [
  "filesystem.read",
  "process.spawn"
]
```

仅表示：

> Plugin requests these capabilities.

不意味着：

> Plugin has these capabilities.

最终：

```text
Requested
    ↓
Host Policy
    ↓
Granted
```

建议：

```rust
pub struct Capability(pub String);
```

Capability namespace：


# 18. Capability Policy

正式定义：

```rust
pub struct CapabilityPolicy {
    pub requested: Vec<Capability>,
    pub granted: Vec<Capability>,
}
```

但：

```text
granted ⊆ requested
```

是硬不变量。

---

# 19. No Auto Grant

新插件：

```text
requested:
filesystem.read
network.connect
```

初始：

```text
granted:
[]
```

或者按照明确 Host 默认安全策略授予有限 capability。

关键是：

> Plugin manifest 本身不能增加权限。

---

# 20. Capability Approval

v0.1 推荐三种状态：

```rust
pub enum CapabilityDecision {
    Granted,
    Denied,
    Unset,
}
```

其中：

```text
Unset
```

表示尚未审批。

不过对运行时而言：

```text
Unset = Denied
```

更安全。

---

# 21. Capability Persistence

数据库：

```text
plugin_capability_grants
-------------------------
plugin_id
capability
decision
updated_at
```

而不是：

```text
manifest.granted = ...
```

Manifest 是包内容。

Grant 是 Host state。

两者必须分离。

---

# 22. Manifest Change

插件更新：

```text
v1.0
requested = [filesystem.read]

v2.0
requested = [
    filesystem.read,
    network.connect
]
```

必须：

```text
filesystem.read
    existing grant

network.connect
    Unset / Denied
```

禁止：

```text
v2 install
→ automatically grant network.connect
```

---

# 23. Capability Removal

v2：

```text
requested = [filesystem.read]
```

v1：

```text
requested = [
    filesystem.read,
    network.connect
]
```

旧：

```text
network.connect = Granted
```

可以保留 grant record，但：

```text
not requested
→ not granted at runtime
```

这样升级回 v3 时可以恢复原政策，或者以后显式清理。

# 24. Runtime Effective Capabilities

最终 runtime 使用：

```text

    requested
    ∩
    granted
    ∩
    launcher_policy
```

因此：

```text
requested = A B
granted = A B
policy = A
```

最终：

```text
effective = A
```

# 26. Manifest Validation 不启动插件

必须：

```text
validate manifest
```

不允许：

```text
validate
    ↓
start plugin
```

Validation 必须：

```text
side-effect-light
```

不能执行插件代码。

# 27. Entrypoint Validation

只允许：

```text

within package root
```

```text

C:\...
\\server\...
```

建议：


```text

.
```

# 36. Update Transaction

更新严格：

```text
Old Active
     │
     ▼
Download / Import
     │
     ▼
Stage New
     │
     ▼
Validate New
     │
     ▼
Install New
     │
     ▼
Health Check
     │
     ▼
Activate New
```

失败：

```text
Old Active
    remains active
```

---

# 37. Update 不直接覆盖 Active

禁止：

```text
C:\...\plugin\
    overwrite files
```

因为：

```text
crash
file lock
partial copy
```

都会导致当前版本损坏。

---

# 38. Versioned Install Paths

推荐：

```text
Plugins\
  com.example.pdf-tools\
    1.0.0\
    1.1.0\
```

Active pointer：

```text
active.json
```

或者 registry 中：

```text
active_instance_id
```

这样 rollback 简单。

# 39. Active Pointer

建议 Host 使用：

```text
plugin_id
active_instance_id
```

启动时：

```text
Registry
    ↓
active instance
    ↓
install path
```

而不是扫描目录猜当前版本。

# 41. Crash-safe Activation

Activation 本身必须：

```text
atomic
```

例如：

```text
write active pointer temp
    ↓
flush
    ↓
atomic rename
```

不能：

```text
truncate active.json
write
```

否则 crash 会让 Plugin 没有 active version。

---

# 42. Rollback

如果：

```text
v1 active
v2 staged
```

v2 failure：

```text
active = v1
```

Rollback 不应该：

```text
reinstall package v1
```

因为 v1 已经存在。

只切换 active instance。

---

# 43. Update Health Check

至少：

```text
process starts
protocol handshake succeeds
manifest identity matches
```

不能把：

```text
process started
```

就认为：

```text
update successful
```

---

# 44. Plugin Protocol Identity Check

Runtime 启动后：

```text
expected:
plugin_id = X
version = V
```

Host 收到 handshake：

```text
actual:
plugin_id = Y
version = V
```

必须：

```text
ProtocolViolation
```

并：

```text
terminate
quarantine candidate
```

避免安装目录/plugin ID substitution。

# 50. Plugin Execute

LifecycleManager **不应该**提供：

```text
execute(plugin_action)
```

```text
ActionEngine
 → PluginBroker
```


# 51. Enable

流程：

```text
enable
 ↓
check manifest
 ↓
check compatibility
 ↓
check capability policy
 ↓
registry.enabled = true
```

默认不立即启动。

除非：

```text
plugin policy = persistent runtime
```

但即便如此：

```text
start
```

也经过 RuntimeManager。

---

# 52. Disable

流程：

```text
disable
 ↓
registry.enabled = false
 ↓
if running
    graceful stop
```

不能：

```text
disable
 ↓
TerminateProcess immediately
```

除非：

```text
graceful stop timeout exceeded
```

随后：

```text
RuntimeManager
```

执行 process cleanup。

---

# 53. Disable 对已有 Invocation

如果用户在：

```text
Plugin action executing
```

时 disable plugin：

v0.1 建议：

> 不取消已经开始的 Execution。

只阻止：

```text
new execution
```

原因：

```text
disable
```

是 lifecycle policy，而不是 execution cancellation。

---

# 54. Quarantine 对已有 Invocation

同样：

```text
quarantine
```

阻止：

```text
new invocation
```

不能直接修改：

```text
active Execution
```

除非 Runtime crash/termination 已经发生。

---

# 55. RuntimeManager 与 Quarantine

Plugin crash：

```text
RuntimeManager
    ↓
on_crash
```

它记录：

```text
Runtime crash
```

然后：

```text
PluginLifecycleManager
    ↓
record failure
    ↓
policy evaluation
    ↓
restart OR quarantine
```

这样：

```text
RuntimeManager
```

不需要知道：

```text
PluginPolicy
```

---

# 56. Crash Budget

已有 RuntimeManager：

```text
max_restarts
backoff
```

Plugin ecosystem 再增加：

```text
plugin_failure_policy
```

但两套 budget 不要合并。

---

# 57. Runtime Restart Budget

表示：

> 当前 Runtime 是否允许重新启动。

而 Plugin Quarantine Budget：

> 这个 Plugin 是否已经不值得继续自动尝试。

例如：

```text
Runtime:
restart 3 times

Plugin:
5 crashes / 10 minutes
→ quarantine
```

这是不同维度。

---

# 59. 哪些 Failure Quarantine

建议：

### 高风险：

```text
ProtocolViolation
IdentityMismatch
Repeated StartupFailed
Repeated ProcessCrashed
```

可触发：

```text
Quarantine
```

### 瞬态：

```text
Timeout
ProcessCrashed once
```

先：

```text
Restart
```

再累计。

### 配置：

```text
CapabilityDenied
```

不应该自动 quarantine。

---

# 60. Quarantine Threshold

建议配置：

```toml
[plugins.crash_policy]
max_failures = 5
window_seconds = 600
```

这里只定义：

> bounded policy

具体默认值由运行测试调整。

---

# 61. Failure Window

不能无限累计：

```text
Plugin crashed 100 times over 1 year
```

导致现在突然 quarantine。

只统计：

```text
recent failure window
```

例如：

```text
last N minutes
```

---

# 62. Quarantine Recovery

只有：

```text
explicit unquarantine
```

才能解除。

或者：

```text
successful plugin update
```

可以自动清除旧 quarantine。

建议：

```text
v2 update
```

作为新的 PluginInstance：

```text
failure history reset
```

但历史记录保留。

---

# 63. Unquarantine

操作：

```text
system.plugin.unquarantine
```

必须经过：

```text
ActionResolver
→ launcher-action
```

不能：

```text
UI → registry
```

直接修改。

---

# 64. Plugin Update 后 Capability Approval

这是高风险点。

例如：

```text
v1:
filesystem.read granted

v2:
filesystem.read
network.connect
process.spawn
```

更新完成后：

```text
effective:
filesystem.read
network.connect = denied/unset
process.spawn = denied/unset
```

即：

> 新能力必须重新进入 approval state。

---

# 65. Plugin Version Downgrade

Rollback 到 v1：

```text
requested capabilities
```

回到 v1 manifest。

原来的 v1 grants 可以恢复。

v2 新增：

```text
network.connect
```

即使曾经：


# 116. Security Invariants

建议正式加入：

### `INV-PLUGIN-001`

Plugin manifest requested capabilities never imply granted capabilities.

### `INV-PLUGIN-002`

Effective capabilities are the intersection of request, grant, and host policy.

### `INV-PLUGIN-003`

Plugin installation never directly executes plugin code.

### `INV-PLUGIN-004`

Plugin update never overwrites the active version in place.

### `INV-PLUGIN-005`

Activation is atomic.

### `INV-PLUGIN-006`

Rollback activates a previously validated installed instance.

### `INV-PLUGIN-007`

Plugin identity is independent of version and install path.

### `INV-PLUGIN-008`

Plugin quarantine blocks new execution attempts.

### `INV-PLUGIN-009`

Quarantine does not mutate or cancel an already-started Execution unless runtime failure requires termination.

### `INV-PLUGIN-010`

Plugin lifecycle management never bypasses `launcher-action` for user-triggered state mutation.

### `INV-PLUGIN-011`

RuntimeId and ExecutionId remain distinct.

### `INV-PLUGIN-012`

A PluginBroker failure cannot corrupt Plugin Registry state.

### `INV-PLUGIN-013`

Plugin Registry never becomes an Effect gateway.

### `INV-PLUGIN-014`

A plugin update introducing new capabilities never silently inherits approval.

### `INV-PLUGIN-015`

A plugin cannot self-install or self-update through its own execution authority.

```text

   ↓

   ↓
```

```text

   ↓
```

# 166. Update Quarantine

成功更新：

```text
v1 quarantined
→ install v2
→ health check success
```

可以：

```text
v2 = Disabled
health = Healthy
```

而不是自动启用。

用户需要：

```text

```

或者遵循明确的 update-preserves-enabled-state policy。

推荐：

> 如果 v1 在更新前为 Enabled，则成功更新后的 v2 自动恢复 Enabled；如果 v1 是 Disabled，则保持 Disabled。

# 172. Plugin Capability 与 Action Requires

某个 Plugin action：

```text
requires:
filesystem.read
```

Resolver：

```text
current granted capability
```

决定：

```text
Ready / Disabled
```

因此 Manifest 的 capability system 与已有 ActionResolver 能直接衔接。

---

# 173. Capability Changes Need Not Restart Launcher

当：

```text
grant filesystem.read
```

后：

```text
Plugin action
```

可以立即从：

```text
Disabled
```

变为：

```text
Ready
```

但如果 runtime 已经运行：

> v0.1 建议 capability change 只对**下一次 invocation**生效。

如果底层 runtime session 已经缓存，则可能需要：

```text
restart plugin runtime
```

来确保 effective capabilities 与 runtime state 一致。

---

# 174. Capability Grant 与 Runtime

严格建议：

```text
capability change
    ↓
invalidate active Runtime
```

然后：

```text
next execution
    ↓
new Runtime
```

否则：

```text
Runtime R1
effective caps = A

Grant changed
effective caps = A+B

R1 still alive
```

会产生 authority drift。

---

# 175. 因此 Capability Change 规则

```text
capability grant/revoke
    ↓
mark runtime stale
    ↓
graceful stop
    ↓
next invocation starts fresh runtime
```

不需要强制 kill。

```text

    ==
```


# 179. Plugin Runtime + Disable

同理：

```text
disable plugin
```

当前 runtime：

```text
Enabled=false
Runtime stale
```

立即：

```text
graceful stop
```

确保：

```text
disabled plugin
```

没有继续持有 active process。

---

# 180. Plugin Runtime + Quarantine

Quarantine：

```text
new executions blocked
current process
    → stop
```

因为 quarantine 的定义是 host safety state。

与：

```text
disable
```

相比，两者都可以停止当前 runtime。

---

# 181. 为什么 Disable 可以停止 Runtime

因为 disable 是 explicit user policy。

之前“不要取消已有 Execution”仍然成立。

所以：

```text
Disable
    → block new executions
    → graceful stop when runtime becomes idle
```

而不是：

```text
immediately kill active Execution
```

如果 runtime 当前 busy：

```text
mark stop_requested
```

在安全边界停止。

```text
    ↓ timeout
force terminate tree
```

复用现有：

```text

```
